### 三、 `Context_Cooccurred(B, A)` 假说的失效边界与最小辨别实验

我完全接受你们的定性：**“生成 $B$ 时上下文中曾出现候选 $A$（同生成上下文）”绝不证明 $B$ 在语义上依赖或修改 $A$**，它与你们现有的“同源消息扩展（同一原始消息派生出的记录）”有本质区别。如果无条件将每次整合时的几十个候选与新产出记录两两连边，必然制造 $O(N^2)$ 的完全子图（Clique）噪声，污染图拓扑并拖垮遍历预算。

若要将其降级为一种**受严格约束的检索兜底线索（Fallback Retrieval Hint）**，其成立前提、失效条件与最小辨别实验如下：

*   **约束定义（防稠密图污染）**：绝不作为 `supports/counter` 进入 `evaluateEvidence` 求值；且不对全部几十个候选连边，仅当新记录 $B$ 与某候选记录 $A$ **共享至少一个已解析的受控实体节点（Resolved Node）或处于极小时间窗内，但 LLM 未声明任何显式边**时，才记录一条极低优先级的单向弱索引提示 `unlinked_cooccurred_candidate(B, A)`（受权限与最多 $k \le 2$ 条配额硬限制）。
*   **该假说必然失败的条件（Falsification Conditions）**：
    1.  **热门实体中心节点爆炸（Hub Node Pollution）**：如果用户围绕同一个高频核心实体（如“父亲”或“小说”）聊了 50 件互不相干的事，哪怕加了共享实体限制，也会把毫不相干的日常琐事与关键设定绑在一起，挤占前台宝贵的 Top-K 窗口，导致**检索精度（Precision）净下降**。
    2.  **上游候选根本未召回**：如果 S3 整合时，旧记录 $A$ 根本没进整合步的候选池，那么“同生成上下文记录”连触发的机会都没有。
*   **最小对照辨别实验（离线利用现有快照，不改主代码库）**：
    *   *实验设置*：取现有五臂轨迹（或六个月稀疏模拟集）的整合步日志。在保持整合 Prompt 和求值器完全不变的前提下，离线对比两种检索扩展策略在后续问答步（如 S6）的召回结果：
        *   **基线组**：当前的词面 + E5 + 有限同源扩展 + 显式依赖扩展，RRF 选 Top-6。
        *   **实验组**：在基线组基础上，若 Top-6 命中的记录 $A$ 存在“曾在某次整合中被召回、且当次整合产出了共享同一主 Node 的新记录 $B$（但无显式边）”，允许在总预算内用 $B$ 替换末尾低分记录（或占 1 个额外槽位）。
    *   *判准*：统计在多步轨迹中，实验组究竟是“成功捞回了像‘改周二’这样被漏建边的关键更新（Recall 收益）”，还是“塞入了同实体的无关噪音导致前台回答质量下降或 Token 激增（Precision 惩罚）”。若净收益 $\le 0$，立即枪毙该假说。
