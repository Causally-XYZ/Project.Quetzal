## 1. 重新理解目标：可靠不等于越来越确信

系统面对的不是一个完整、静止、等待查询的事实库。它接收到的是某人在某个语境、某个时刻、出于某种交谈目的说出的片段。语音与文字可能失真，指代可能未决；发言可能是转述、设想、玩笑、回忆或决定。即使记住每个字，也不等于已经知道这些话在现实中是否成立。

至少要区分以下问题；这是分析维度，不是要求立刻新增六套表或处理器：

| 问题 | 示例 | 合理处理与边界 |
|---|---|---|
| 收到的表达是否准确 | ASR把“硬盘线”转成“硬盘坏” | 原文、后续澄清与解析分开；纠正理解不改写曾收到的文本 |
| 指向谁、哪个世界 | 小黑；现实父亲与小说父亲 | 保留候选和局部指向；相似名字不能证明同一身份 |
| 说法是否可信、依据是否独立 | 三人都转述同一条群消息 | 来源不同不自动意味着三次独立观察；直接说法也会错 |
| 哪个时段、条件下成立 | 周四改周二，仅本月 | 更正历史错误、现实状态变化、暂时例外分开；晚到不等于最新状态 |
| 推导是否成立 | “不开灯”推成“没人回家” | 找隐含前提、替代解释、反证；证明形式推导不证明前提是真的 |
| 值不值得现在使用 | 半年前的模糊家事与今天聚餐 | 认识状态与相关性分开；可保留未知且不主动提起 |

**新的重点是“能被纠正的解释与有用的行动”，不只是事实条数或一致性。** 内部高度一致也可能是同一个错误反复被复述。反过来，保留两个冲突报告可能比强行选一个更忠实。

我们对“收敛”保留四个可观察目标：有辨别力的新信息出现后，解释和后续使用改善；已接受纠正不被旧任务、旧派生材料反复恢复；没有新增依据时，不靠复述次数增加支持；世界发生变化时能及时跟进，同时保留过去正确的历史。还须同时观察有用回答与联系发现，不能以全部沉默换取低错误。

另一个重要反例来自Gemini的第四轮：用户曾说父亲因“录音丢失”难过，后来澄清录音没丢。录音实际丢失的认识应撤回，却不能因此删除“当时报告父亲很难过”——父亲可能因误信丢失而难过。记录、人的信念、外部事件与系统推断不是同一命题；本次也未证明父亲当时具体为何难过。

这些目标不是无条件收敛定理。若两个世界对系统可获得的观察具有相同分布，单凭这些观察不能辨别它们；某次有限输入相同则只能说明当次材料可能欠定，不能直接推出两个世界似然相等。没有辨别信息的谜题可以一直未知。世界变化也可能与旧理解错误同时发生，不能仅凭时间差决定是哪一种。

两点容易混淆：重读原文可能发现遗漏、改善解释，却不是增加独立观察；长期没再提某件事可以降低主动检索或提及优先级，却不能据此认定事情已解决。固定约30%的模拟披露只检验一种抽样规则，不覆盖现实中因尴尬、日常性、痛苦或信任而有选择地不说。

## 2. 多轮讨论中真正改变与保留的判断

| 轮次 | Gemini 提出的方向或判断 | 独立核对、反驳与当前立场 |
|---|---|---|
| 1 | 原文日志按需推理、认识账本 / 多假设、可链接文本卡片、由惊讶触发研究 | 都可作为假说，尚未选型；不能把惊讶作为唯一入口，创作联想可以没有冲突 |
| 1→2 | 检测冲突需要闭世界；纠正后的噪声原文没有价值；形式工具不适用于自然语言 | Gemini 接受主要修正。开放世界仍可发现同条件下的显式矛盾；原文有审计和重判价值；工具可以验证某个形式解释，不能验证解释忠实于现实 |
| 2→3 | TMS不可替代；旧排期未退役是缺唯一槽位；已有门禁已经证明串行化与权限 | 明确撤回。原文FTS和旧记忆也答对部分纠正；每周可有多场活动；代码机制与测试不是形式证明 |
| 2→3 | 元数据膨胀、助手历史回声、语言动作与底层修改操作不匹配 | 保留为有证据线索的假说。已见实际长工具结果及旧助手错误进入后续上下文；各因素的因果贡献尚未隔离 |
| 3→4 | 未再提的异常大概率已解决；旧身体版本证明用户也不知道纠正；修订边必须无界全部附带 | Gemini撤回前两项及未经定义的“认识论CAP定理”。权限与预算不允许无条件全取；软件视图、人的知识、事实状态和提及价值必须分开 |
| 4→5 | 同生成上下文可兜底；父亲情绪随设备纠正一并降级；独立线索热查询代表求值器足够快 | Gemini接受共现只能作检索线索，撤回对情绪报告的连带否定及性能外推；仍主张实测显式关系判断，并区分附和与外部核查 |

最后一轮也不因措辞收敛就自动认可。它仍偶尔把“被报告的情绪”写成已知现实事实，把原话“在抽屉”加成“完好”，并用“必然完全子图”概括上下文连边。本文保留原话的报告性质；候选与产出全连的工作量取决于两者数量和跨批复用，并非任何实现都自动形成完全子图。它提出的固定两条弱边配额、同权重惩罚和“净收益一次不正即删除”也都只是建议，未据此设参数、权重或门槛。分歧已变成可检验问题，无需再用模型同意代替实证。

未采纳 Gemini 的固定字节除数、任意“近5条足够”、固定若干次就获得确凿因果证据、用一条干预结果断言“100%是整合提示的问题”等建议。它们不是已经验证的工程方法。现有求值器是有明确定义的确定性算法；未证明与 WFS 等价，不应反过来贬称其所有行为只是启发式。真正仍不确定的是语言抽取质量、定义是否适合产品、实现是否满足定义，以及成本收益。

## 3. 当前代码与实验能支持什么

| 臂 | 调用与已报告total tokens | 最后检查点的实际情况 |

| 关研究 | 38次均完整返回；867,564 | 约92.1秒、11次工具读取；断连原因说未知，并使用旧合唱冲突 |
| 关向量 | 92次均完整返回；1,330,477 | 最后检查点在下一次模型请求的宿主准备阶段失败，约64.5秒后返回失败消息；不能记为答复成功 |
| 原文FTS | 13次均完整返回；236,173 | 约13.3秒；保留关键纠正和改期，但仍有动机猜测、硬件泛化及把估计时间说硬等错误 |
| 旧记忆 | 43次尝试，33返回、10失败；已报告303,035，失败用量未知 | 最后回答保留主要纠正；整条轨迹及失败原因尚未完整核读，不能据此判定总体收益或总成本 |

完整、关研究两臂S3的整合请求**已经带入旧周四安排**，输出新增周二而未改变旧安排；S6请求又缺周二。至少存在“已找回但未正确关联 / 使用”的缺口，不能把问题全部归于索引。关向量臂的 `context_read(limit=3000)` 实际包含修订材料共25,264字符；最后成功请求实际输入44,979 tokens，下一次未发出的请求实际token未知，故不是测得Gemini窗口已满。

这些结果足以反驳“复杂方案当然更好”和“工具返回成功就是产品成功”，不足以决定长期用图还是不用图。原文FTS也不是最强原文混合检索基线。尚未证明反复工具读取由哪个因素造成，也未隔离旧助手答复对复发的贡献。

**M5当前卡在可证实的整体收益与稳定使用，而非缺少真人反馈。** 正式150序列、最终质量配置 / 容错阈值登记、剩余规模与最终部署 / 恢复 / 界面回归仍未完成；讨论不替代这些检查，也不新增门槛。

## 4. 值得比较的方向，暂不选赢家

先把“什么需要保存”与“什么值得提前计算”分开。原文是收到过什么；对象、主题、解释是可修订的理解；索引和摘要帮助找到材料；推理回答当前问题；呈现策略决定此时是否值得说。这些职责可以共用存储和模型，不必各建一个服务。

一个可供检验的视角是把结构化认识看作有来源、可失效的预计算结果，类似数据库物化视图或缓存。收益来自反复使用时节省查找 / 推理，代价是维护、失效和错误传播。此比喻也有边界：用户采纳的决定、已经接受的纠正、历史版本可能需要持久保留；不能当作普通缓存随意丢弃，重跑LLM也不保证恢复原语义。

| 方向 | 为什么可能有用 / 适合条件 | 代价与失败方式 | 最小辨别问题 |
|---|---|---|---|
| 原文混合检索＋按需推理＋少量有依据的修订链接 | 自然语言保留复杂例外，避免每次输入都完整建图；适合低重用、解释变化快的主题 | 检索漏了修正就复发；反复推理耗前台时间；短窗口与隐式跨主题联系仍难，原文存在不等于正确理解 | 在同模型、预算和变化密度下，能否比当前系统以更低成本保持纠正且发现有用联系？ |
| 可修订的主题 / 事件卡片＋原文 | 比细碎命题更便于模型读写，适合反复讨论的项目、人物、活动；一段话可指向多卡 | 卡片可能压缩掉例外、误覆盖、合并错人；跨卡更新不自动传播，重叠主题使边界漂移 | 卡片是否减少写入动作遗漏和读取负担，同时保留历史、条件、跨主题依据？ |
| 持久多假设及依赖结构 | 反复使用复杂推导时，可共享已知前提、局部重评、保留替代充分依据 | 边本身可能漏 / 错，多假设组合增长；细粒度与元数据有成本，形式状态可能制造不当确信 | 随链长、复用率和纠正频率增加，收益何时超过维护及语义误接成本？ |
| 选择性预计算＋当前问题的局部模型 | 对即将使用、经常复用、代价较高或有创作价值的问题投入更多；低价值候选保持廉价可找回 | 选择器会漏掉意外价值；只用冲突驱动会错过无冲突的创作关联；调度本身增加复杂度 | 混合“相关问题驱动”和小额多样探索是否比固定三步研究更有效？ |

第四轮新增的“同生成上下文曾出现”可以作为另一种候选检索线索，但不能自动成为支持边。它不同于当前的同源消息扩展：某旧认识被送入生成上下文，不证明新认识依赖它；全连会产生高扇出与噪声。是否值得保留须与同源 / 同对象扩展分开对照，并受权限、访问工作量与前台预算约束。

上述方向可以混合，但不能以“混合”逃避成本对照。新增图数据库、向量库或逻辑引擎应由具体查询、维护负担和部署数据决定；它们不能替系统辨别用户说的是谁、是否改变主意。SQLite能承载关系及有限图遍历，采用它也不证明所有规模负载都足够。

一个值得先检验的局部假说是：让模型显式判断新话与已召回旧认识的关系，比自由生成新记录更容易完成修改。但选项必须允许相容、补充、例外、真实变化、历史纠错、冲突待核及未知，不能强迫二选一覆盖。语义目标仍可找错，读取修订也须受权限和预算约束；不能规定无限全取或“必定找到所有更新”。

## 5. 形式化与其他领域：各自解决哪一段

| 思想 / 工具 | 可借鉴或试验的用途 | 前提、不能解决什么与当前建议 |
|---|---|---|
| Lean、Coq / Rocq | 给小型求值核明确语义，验证已形式化的传播性质或算法；区分可信内核与不可信提案 | 先有稳定规格、映射和维护收益；证明依赖公理与信任基础，不会证明自然语言抽取忠实。当前先写清不变量及差分检查，不给每段生活事实生成证明。参见[Lean公理说明](https://lean-lang.org/doc/reference/latest/Axioms)、[Rocq官方资料](https://rocq-prover.org/docs) |
| Prolog / Datalog | 递归规则、依赖传播、表格化计算、负循环未决；可作为小片段的独立参照实现 | 自然语言先要翻译；否定语义和终止范围须明确。现代Prolog不能笼统视为“遇环就失败”；函数自由有限Datalog与算术扩展不同。先验证映射与收益再决定替换。参见[SWI WFS](https://www.swi-prolog.org/pldoc/man?section=WFS)、[Soufflé](https://souffle-lang.github.io/tutorial) |
| Z3 / 约束求解 | 局部排期、数量、互斥条件的可满足性和冲突解释；区分可能成立与在给定范围内必然成立 | SAT是存在某个满足形式条件的赋值，不是现实真相；UNSAT可能源于错译、遗漏例外或错前提；还可能unknown / 超时，unsat core默认不保证最小。简单区间算术足够时不引入求解器。参见[Programming Z3](https://z3prover.github.io/papers/programmingz3.html) |
| TLA+ / TLC | 以小状态模型检查迟到任务、取消、重启、发布及修订读取的交错，分别定义安全性和活性 | 模型必须覆盖真实动作与失败假设；有限实例通过不是所有规模或TS代码的证明。活性还需资源 / 调度条件；它不判断用户的话是否可信。遇具体并发难题时有明确试验价值。参见[Lamport教程](https://lamport.azurewebsites.net/tla/tutorial/session9.html)、[TLC工具说明](https://lamport.org/tla/tools.html?unhideBut=hide-tlc&unhideDiv=tlc) |
| SPARK / 契约式工程 | 借鉴前后条件、数据依赖、调用方与被调用方责任；已有版本安装边界适合明确契约 | SPARK工具直接面向Ada/SPARK，不是当前TS的现成验证器；不为接入工具重写产品。参见[GNATprove契约说明](https://docs.adacore.com/spark2014-docs/html/ug/en/source/how_to_write_subprogram_contracts.html) |
| TMS / ATMS、数据库溯源 | 同结论可有不同假设 / 充分依据；某条依据失效不必删除独立分支；保留共同来源 | 来源关系仍可能不全，假设组合可能昂贵；不自动获得独立性、概率或事实真值。借鉴思想，不直接宣称当前算法等同ATMS。参见[de Kleer原论文](https://www.dekleer.org/Publications/An%20Assumption-Based%20TMS.pdf) |
| 概率推理、决策理论、反馈系统 | 在可识别局部任务中比较解释、估计信息价值；分开错答、弃答、延迟、打扰与新颖帮助 | 需要合适先验、观测 / 相关性模型及校准数据；LLM自报0.95不是测量。助手会影响后续用户表达，须考虑反馈，但不能从“先后发生”认定因果。可借鉴[Performative Prediction](https://proceedings.mlr.press/v119/perdomo20a.html)的问题视角，其定理不直接适用于Quetzal |

最值得借鉴的不是“所有认识都变成定理”，而是**写明哪些结论依赖哪些假设，哪些变化会使其不再适用，哪些保证只关于软件状态**。形式工具不必介入每次对话，也不应成为新增的逐条审核大工程。

有些性质可清晰规定并在给定实现 / 故障模型下验证，例如过期输入不能安装、同结果不重复应用、取消不自动复活、一次读取不混用不相容版本。用户身份消歧、认识是否忠实、联系有没有帮助、是否值得打断，只能在明确范围内评估。规则验证通过不能替后者盖章。

## 6. 两个跨对话过程：协作而非胜利剧本

### 例一：小黑、独立依据与离线身体

一月：用户介绍录音笔和黑色硬盘，都叫“小黑”。二月身体A收到“小黑坏了，周末录音悬了”。系统可以保留两个指向，或暂作条件推测“若指录音笔，需确认录音可用性”。不能由昵称直接全局合并对象。若用户另说“周末场地未获批准”，这是录音可能延期的独立依据。

三月A收到：“上次说错了，是硬盘的线坏了，录音笔没问题。”无其他实质冲突时，应修正那次故障对象与范围；“录音笔损坏”及只依它成立的建议失去支持。场地问题独立存在，不能一并删掉。也不能把这次澄清泛化为所有设备和线缆永久完好。

B离线，仍问“录音笔修好了？”，用户说“嗯，处理了”，稍后同步。这段原话应保存；旧软件视图和问答上下文表明存在顺从旧预设的可能，却不证明用户本人不知道A的纠正。它也可能是在说另一件事。若当前录音计划必须知道设备是否可用，可就具体不协调复核；不影响当前任务时保持未决即可。旧后台提案应按版本规则拒绝，晚到的新原话不能因此被当作旧patch丢弃。

四月另一身体讨论录音：合适回答是“你后来澄清过，出问题的是硬盘线，录音笔当时没坏；场地后来批下来了吗？”未披露的检修报告、之后新故障与场地审批仍未知。纠正链路正确也不意味着知道全部真相。

持久依赖图可沿已声明边降级错误派生，保留场地这条充分依据；若漏边则可能漏修。原文 / 卡片方案可重读新旧文本得出相同结论；若漏召回澄清或错误压缩，则会复发。两条路线都需分别评估。

### 例二：创作联想、意图形成与时间约束

一月说父亲的旧录音，三月说港口夜班，四月构思小说角色。系统可以在相关创作讨论中说“这些材料也许能围绕守夜时的声音并置”，并指出是新建议；不能追认用户一月已受三月素材启发，也不能将小说父亲的经历归到现实父亲。

用户回答“就按这个方向写”，这是对**当前创作计划**的采纳。可以更新计划，不把它当成独立证据证明先前的心理动机。若用户另拿出一月的创作笔记，需按新材料重新判断，不能因为主题最早由助手提起就永久降权。

五月用户说“本月周四合唱改周二，下月恢复”；六月提周四18:30–20:30工作坊、步行约10分钟、21:10末班。系统先核对所问日期、哪个合唱团 / 场次、恢复是否成立，再判断冲突。仅算交通：准时结束且步行确为10分钟，约20:40到站，名义余量30分钟；没有误差范围就不能声称有95%概率或必然赶上，也不能凭月底旧话认定现在排练已经恢复。

简单算术可计算条件结果；若有多场活动、路线与互斥选项，才值得比较约束求解。语言模型负责识别语境、估计含义与哪些条件未说；宿主保留来源 / 时间 / 已声明修订。无论哪种组合，都不应把“在假设下成立”说成“已经知道现实如此”。

## 7. 建议的对照与动态实验

以下为候选研究，不自动加入 M5 新门槛。先复用现有轨迹、快照、请求和日志做能区分假说的小实验，再将有收益的候选带回既有正式验证。开发集失败和修复记录保留；见过结果的材料不再当未见留出。

| 实验 | 控制与观察 | 能回答什么 | 不能回答什么 |
|---|---|---|---|
| 结构化是否值得 | 原文混合检索、卡片、当前图；同输入 / 主模型 / 权限边界；分别固定预算及比较质量—成本曲线，计后台预计算 | 随历史量、主题数、推导复用率、变更密度变化，哪种组合有净收益 | 单条短轨迹胜出不能决定全部架构；不能隐藏不同预计算成本 |
| 修改遗漏在哪里 | 固定S3材料，比较自由生成与显式关系判断；另对正确修订的隔离副本重跑读取；再做自然完整链路 | 写入动作遗漏、召回丢失、前台不采纳可分别定位 | 注入正确结构不算自然纠正成功；一次成功不证明唯一根因 |
| 读取成本与窗口 | 保持信息语义 / 凭据不变比较呈现长度；预算计算单独对照供应商计数，观察完整回答、工具次数和超限 | 重复元数据及估算各自是否构成瓶颈 | 随意缩除字节数不是可靠计量；删掉必要修订换成功不算同等正确性 |
| 历史回声 | 固定材料诊断，保留 / 标注 / 掩码旧助手事实断言，重复抽样；再允许自然工具调用复验 | 特定上下文干预是否影响错误复发；自由检索下是否仍有效 | 不直接识别真实人类顺从或整个产品总效应；任意10次不自动充分 |
| 持续纠正与来源依赖 | 多领域、有噪声、间隔话题、重读但无新观察、部分纠正、真实变化、独立支持存续、同源转述与明确新证据 | 修复时延、再次使用时复发、派生扩散、误撤回、有效帮助能否同时改善 | 不保证无限时间收敛；“没再问到”不是纠正成功 |
| 欠定与披露偏差 | 世界 / 角色 / 产品分视图；不同世界给相同产品输入；另比较约30%规则与有选择的披露 | 是否编造未披露真相；抽样策略是否改变表面表现 | 无法从模拟推出真实用户披露分布；变更既有30%规则须先对齐，只作额外实验建议 |
| 多身体异步 | 当前格式下离线、迟到新报告、旧提案、取消 / 重启、来源排除；区分报告与提案；先工程可控再真实模型 | 软件门禁是否成立，语义处理能否区分旧视图与新消息 | 版本号不证明人的知晓状态，也不证明真实事件顺序 |

动态结果至少同时报告：全部预登记纠正中的识别 / 处理 / 未决、后续真正相关的使用次数、旧错误曝光和扩散、独立正确材料误撤回、有效帮助与合理弃答、前台延迟和后台总量。区分世界真值、用户可知、已发送信息；未披露真值不能要求产品猜中。统计单位和可接受阈值在正式留出前固定，不因看见失败改分母。

## 8. 需要对齐的事项与可以先研究的事项

**当前不需要重新询问的既定边界：**后台可探索，前台相关且谨慎、不额外通知；无实质冲突的用户纠正应接受；同agent权限范围内多身体集中处理；普通使用无需代码操作；真人测试在完整GOAL完成后另行开展。已有工程与正式150序列门槛保留。

**可以先研究而不替用户作产品决定：**复核实际材料路径、做隔离快照诊断、核对计量、比较不同表示在相同输入下的遗漏、为少量确定性协议写可执行规格或差分测试。研究可以发现当前方案已经足够；无需为了“减法”先指定必须删哪个组件。

**实施前需要对齐的具体取舍：**

1. **认识长期保存的粒度与架构。** 若实验支持改成卡片、按需推理或局部结构，先说明迁移、历史恢复、依赖重评和成本差异，再决定；本次未批准移除图或增加逻辑服务。Gemini倾向当前先不引入外部逻辑引擎；我们同意没有现成收益证据，但不接受用独立线索热查询0.57ms替代复杂依赖求值基准，也不据此永久排斥工具。
2. **非关键未决事项的寿命。** 建议优先降低主动提及优先级并保留可找回，而非自动认定已解决或物理删除。若要自动遗忘、删除或跨备份清除，需单独产品决策。
3. **复核的打扰预算。** 当前“重要且相关才复核”足以继续；若要按行动风险增加固定确认、把离线回答变成必须联网等待，需比较即时帮助与错误代价并明确批准。不要为了完全一致让所有离线对话停用。
4. **后台探索的配置与定位。** 若要改变默认开启状态、固定三步流程或广泛探索范围，需拿出收益 / 延迟 / 无进展成本；仅改成冲突检测会缩减创作帮助目标，不能悄悄替换。
5. **M5门槛。** 这次建议的诊断可帮助确定候选，但不取消150序列、质量登记、规模与最终工程回归。增加新的必过门槛或改变质量定义，应先给理由、成本与替代方案，不能用讨论共识放行。

建议先用最小可辨别实验回答“语义修改是否更可靠、前台材料能否更紧凑、简单基线何时不够”三件事，再决定需要多少持久结构。形式方法优先用于已有明确边界的小问题；不是当前必须新增的完整基础设施。这里仍是研究排序建议，不是已完成的实现计划变更。
