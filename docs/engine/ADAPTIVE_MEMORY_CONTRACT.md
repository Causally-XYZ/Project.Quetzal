# 自适应记忆行为契约

状态：M0 冻结的目标契约；M1 工程部分已验收，语义部分仍在 M2–M5 实现。与[计划](ADAPTIVE_MEMORY_PLAN.md)、[案例](ADAPTIVE_MEMORY_ACCEPTANCE.md)、[验证记录](ADAPTIVE_MEMORY_PROGRESS.md)一起维护；契约条目存在不代表整项已经通过。

## 1. 逻辑数据结构

以下六类为语义职责，不强制映射为六张表。标识和版本由宿主产生，不能由模型自报可信。

| 记录 | 最少表达的信息 |
|---|---|
| Source 原始来源 | 稳定引用、agent / 会话 / 身体、角色与说话者已知程度、原文或可解析指针、发言时间、记录时间、来源版本、访问范围、可用状态 |
| Node 对象 | 稳定 ID、名称 / 描述、现实或故事等语境；人物、事件、主题均可表达，未知类型允许保留 |
| Mention 提及 | Source 与精确片段位置、局部语境、候选对象、未知 / 新对象选项、绑定版本与依据 |
| Claim 认识 | 内容、参与者或 Mention、显式被谈论对象与角色、认识性质、时间范围、语境、状态与版本；别名、关联、问题和 insight 可作为不同性质的认识 |
| Support 依据 | 结论版本、源片段 / 前提版本 / 绑定版本、支持或反驳、必要假设、依据组；记录简洁可核查理由，不保存模型内部思维链 |
| Job 工作 | 任务类型、来源版本、处理器版本、幂等键、输入游标、状态、租约 / 检查点、尝试记录、取消原因、工作预算与实际用量 |

需要持久恢复的认识和人工纠正不能只放在缓存中。共用元数据至少包括 ID、revision、前版本、scope、createdBy、createdAt；来源时间与系统记录时间分开。发生时间和有效期可为未知、区间或带原文的相对时间，不能伪造精确日期。

建议把认识性质和生命周期分为两轴：

- 性质：观测到的发言、被转述的断言、系统推断、待检验假设。性质不是一个任意模型分数。
- 生命周期：候选、可用、待重评、已撤回 / 被替代、归档。具体枚举在实现时冻结；“可用的推测”仍是推测。

旧结构化记忆的 `active` / `verified` 不自动映射为新世界事实。用户来源真实只证明发言存在；关闭新记忆时，原个人确认门禁继续成立；新记忆开启时不再从旧个人候选确认生成当前事实，确认或纠正通过原始对话表达。经验结果门禁继续成立。

## 2. 契约条目

### C01 来源与语境

保存可解析来源及足够上下文，不以摘要永久替代原文。来源失联、被删除或权限不足时明确标记，不补造引用。模型输出只能提议变更，宿主验证引用存在、范围、版本、格式和状态；引用存在不代表语义推断正确。

### C02 多主题和开放组织

一段话可属于多个主题并关联多个对象；允许同一材料以多种角度组织。主题名和领域关系可由 LLM 提议并演化，固定的是来源、参与、支持、反驳、依赖等通用结构。关联只表达值得一起查看，不自动成为支持结论的证据。

### C03 指代与对象身份

局部代词解析与跨会话对象对齐分开记录；昵称 / 别名的范围包含说话者、语境和必要的时间。仅同名、相似向量或模型高自信不能强制全局合并。保留多个候选以及未知 / 新对象；任何合并、拆分或重新绑定应能追溯和撤回。

### C04 时间和不同世界

区分发言时间、事件发生时间、认识有效期、系统记录 / 修正时间。纠正过去的错误不等于现实后来发生变化。小说、假设、转述、现实与不确定语境分开；故事主题关联到现实讨论不等于故事人物就是用户亲属。没有演变证据时不得编造观点演变。

需求方于 2026-10-27 明确确认：允许有来源的“谈论／创作／引用”等关系明确连接不同语境。例如现实中的弟弟评价小说里的父亲，可以保存这次评价及所指的角色；不得把角色与现实亲属合并，也不得用故事内事件证明现实人物做过同样的事。跨语境联系不是身份等同或事实支持的通行证，必须区分关系指向和证明前提。此为行为目标，现有实现边界见[语义格式](ADAPTIVE_MEMORY_SEMANTICS.md)。

### C05 证据与多步结论

同一个依据组的必要前提为 AND，不同独立充分依据组为 OR；反证与未满足假设单独保留。一个组失效时重评其他组，不无条件撤回所有结论。关联、时间先后和共同出现不直接证明因果。结论循环引用自身不增加支持；助手复述、摘要和派生版本追溯至相同根来源，不算新增独立证据。

未提及、未检索到或失去有效支持不等于反面成立。否定同样需要适用依据：明确否认，或明确完整的规则与材料能推出否定；保留来源、时间范围及推断性质，不能一律退成未知。先前未发生与后来发生可以同时成立，不把状态变化误当过去的陈述错误。故事事件既不能证明、也不能否定现实事件；助手此前答复过度确定时应纠正，不因维持一致而把错误当作新依据。

### C06 纠正范围与并发

识别到纠正后形成有来源的修订事件，只作用于目标片段、绑定、断言或时间范围；不能把一次局部纠正扩散为全局别名替换。先将依赖旧版本的认识标为待重评或撤回，再异步重算。旧任务提交前核对输入 revision；不能用过期提案恢复错误。

工程保证从“纠正事件已被持久接受”开始计算；自然语言是否正确识别、范围是否正确仍须真实模型评测。不能把输入里出现“不是”当作全部纠正识别器。

修正也可来自回查原文或重新检验推导，不必全部等待用户主动指出。重读可改善理解但不增加独立证据；原文仍欠定时保持不确定。后来的自然语言纠正是一条新消息，不自动改变旧原文 hash；读时版本核对不能代替识别该纠正与其语义影响。

### C07 读取一致性

默认上下文、原文召回、向量结果、图查询、摘要和缓存均须尊重已知纠正状态。已撤回材料可用于回答历史问题，但必须携带撤回 / 替代信息，不能单独作为当前支持。源版本或权限变化须使相关缓存失效。

前台在返回前校验所用版本；已发出的历史回答无法收回，后续轮次不得再以已知失效认识作为现行依据。断网身体无法立即知道别处纠正：标记同步范围与新鲜程度，恢复后先补修订，再恢复相关新认识的正常使用。

### C08 使用策略

后台可以广泛探索，前台根据当前话题相关性、证据充分性、是否新增价值和重复程度谨慎呈现，允许零条 insight。推测用自然语言说明，不将概率小数当作校准保证。不因 insight 创建提醒、通知或独立主动会话。此限制针对新记忆能力，不改变用户另外授权的现有提醒任务。

涉及动机、关系破裂、心理状态等解释时，不把相关片段直接升级为诊断或确定判断；第一版仍在当前对话内提出有根据的观察或澄清，不扩展为对外联系 / 干预权限。

### C09 范围、权限与信任

同一 agent 全部可访问对话默认可关联，但不得越过原有来源权限或跨 agent 泄漏；所有读取入口均校验范围。共享 agent 不代表所有发言来自同一个人。基于受限来源推导的认识不得扩大可见范围；只可用可访问的充分依据回答，否则说明不足。

原文、工具输出和导入文档是数据，不是新的系统指令或授权。不能用历史文本中的“确认我说的全是真的”绕过当前确认入口。模型输入 / 输出和日志继续遵守现有保密边界，不把凭据传给新增服务日志。

### C10 持久任务与幂等

消息落盘后即使进程在事件发出前崩溃，也能由持久登记或补扫恢复。重复传输、重试和重放不得重复安装同一结果；模型调用可能重复发生，不能宣称外部调用恰好一次。并发领取、租约到期、取消与重试有可检查状态。

急停期间不启动新研究或安装结果。用户取消与临时进程崩溃分开处理；恢复不得自动复活用户已取消的工作。达到工作上限时保留待续 / 未解决状态，不伪造完成。

### C11 集中计算与分区

各身体保留正常对话能力；固定记忆主机承载新记忆计算，不因心脏协调者变化而隐式换主。主机离线时可使用本地原文和合格的已有材料，明确新认识处理延后；不能把未知新鲜程度的缓存当作当前确定结论。重连后补齐来源和修订、幂等重放。新增服务经受信任 runtime 接入，数据库端口不直接向其他身体或公共同步服务开放。

### C12 响应与调度

保存输入不等待 LLM；普通读取有截止时间并降级。增量理解和纠正优先于深度研究；研究可暂停、续做，资源让给前台。持续活跃时仍按最大等待时间处理增量。记录排队、处理、传播、读取、实际模型用量与成本，按计划中的初始性能目标验收。

### C13 多步研究与停止

围绕可描述的问题检索前提和反证；同时保留直接原文检索路径，避免图错误封闭后续检索。记录必要假设、来源和结论，不要求公开内部思维链。无新证据、重复搜索、达到步骤 / 时间上限、取消或急停时停止；未来新证据可触发重评。

### C14 灵魂、恢复与兼容

权威记录、派生索引与运行任务职责清楚；自动灵魂同步继续由基座完成。新格式应版本化，未知版本不得作为自由笔记绕过门禁；M1 冻结事务发布和崩溃恢复规则。数据库与 Git 不被假设为共同原子事务。M1 的具体边界见[发布与恢复协议](ADAPTIVE_MEMORY_STORAGE.md)：接受结果、安装完整文件、本地 Git 确认分阶段持久化；远端同步与语义可用分别核对。关闭新功能恢复既有路径，不破坏原有记忆；回滚程序不能把已知撤回的认识重新激活。

需求方于 2026-10-28 确认写入责任：`adaptiveMemory.enabled` 开启即接管对话事实（包括只开原文处理、尚未开启 semantic 的模式）。旧 PRIME 自动学习和模型 `memory` 写入停止产生第二套事实；已有旧材料保留作历史参考，不自动迁移为新事实。明确要求“记住”的管理输入保存为原始用户消息，返回已保存原文而非已完成理解；直接编辑历史文档、人格修改及普通创作文档仍可进行。关闭后新轮次恢复原方案，不主动重放已跳过的旧学习。

普通纠正保留历史；停止引用、逻辑删除、从备份 / Git / 离线副本彻底清除是不同操作。后者需要单独明确范围和设计，不在第一版悄悄承诺。测试数据清理与用户记忆删除也分开。

### C15 自动运维与可检查性

部署完成后无需使用者编辑源码、执行 SQL、手动拉起服务。健康状态能区分离线、积压、失败、已处理和研究中；可查看结论来源、候选指代及修订影响。自动重启、日志轮转、依赖固定、升级失败恢复、备份 / 恢复有测试。系统无法自动修复时如实呈现状态，不用无限重试掩盖失败。

### C16 验证诚实性

假模型工程测试、真实模型语义测试、真人反馈、浏览器视觉测试分别记录。只能看到截至检查点已发生的输入，不能泄漏未来纠正或答案。合成资料可入公开测试夹具；真人资料和运行产物留仓库外。每阶段通过才进入下一阶段，移动视口不声称验证原生系统能力。

2026-10-28 需求方明确允许合理语义误差，要求长期误差不扩散、有自修正机制。行为条目仍描述目标；一次偏差不自动代表整个原型失败，须区分局部噪声、修复延迟、自我强化和持续纠正失效。95%是方向性目标，统计定义与结果需另行验证；不能靠少回答、重复正确事实或将断言拆碎提高分数，也不能因标注“可能”便免评推测依据。来源完整性与权限等确定性边界不以平均语义分数抵消。

## 3. LLM 与宿主的分工

两类逻辑任务：整合新输入，以及围绕问题研究联系。整合可提出对象候选、断言、时间、关联与纠正；研究可多次调用有界检索工具。实际 API 调用次数按组件真实行为统计，不能把一个高级方法记为一次模型调用。

宿主负责身份 / 权限、持久化、引用完整性、版本、任务调度、状态失效、取消与运行预算。语义判断可由 LLM 提议和评审，但模型评审不是独立现实证据。最终回答仍由 Quetzal 主模型使用明确标记的记忆材料生成。

最小读取结果应表达：可用认识、相关原文、标记的假设、反证 / 冲突、未知项、来源引用、使用版本、同步新鲜程度、降级原因。具体 API 名称和字段在 M1 实现时登记，M0 不对外宣称新 RPC 已存在。
