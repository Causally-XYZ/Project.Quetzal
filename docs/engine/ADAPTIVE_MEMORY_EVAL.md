# 自适应记忆：M2 语义评测登记

状态：开发评测准备，留出集未开启。通用断言见[验收案例](ADAPTIVE_MEMORY_ACCEPTANCE.md)。本页先登记评分口径，不能因开发案例通过就放行 M2。

## 1. 提案接口 v1

`adaptive-proposal.ts` 提供 `proposalPrompt` 和 `normalizeProposal`。模型看到宿主分配的来源 s-key、已有记录 r-key 和语境句柄，输出 `{contexts,records}`，新 / 修订记录使用 p-key；replace 指向待修订的 r-key。宿主生成 UUID、连续版本、来源 hash、精确 UTF-16 引文位置和整体代次。重复制式引文未明确 occurrence 时拒绝，不任意选择第一处。旧版本 / 已失效来源在提示材料中显式不可用，不自动指向最新版本。语境声明仍逐项校验类型、唯一句柄和精确出处；合法但没有记录引用的声明不落库，也不阻止其他独立记录安装。它不放宽实际记录的跨语境引用规则。

模型输出只是提案：格式 / 引用验证、语境隔离、版本安装和原文语义理解是不同层。结构合法的错误理解仍算语义失败。空提案允许表示没有新认识，但不能用普遍弃答掩盖漏提取。既有个人确认规则保持不变。

编辑原文后，输入 `sourceChanges` 列出旧依据失效的记录与可读的新来源句柄；旧引文保持 unavailable，不能自动换 hash。重评同时提供 `review.candidates`，包含同语境已有对象及定义，目标仍只允许修改一条既有记录。对象是检索候选，不是等同身份的结论；同名归并或重复造对象仍计入语义核查。原文删除 / 忽略后的工程隔离与真实语义修订质量分别验证，不能据替身回归认定真实模型通过。

输入额外提供 `dependents`（r-key → 当前精确版本的直接下游 r-key 列表），供模型在同批纠正中检查依赖，而不盲目更新版本引用。开发报告的 `reviewCandidates` 是纠正前快照中传递受影响、但本批未修订的记录引用；它不表示这些记录全部失效，也不能代替待重评任务队列。提示要求拆开可独立纠正的吃饭事件、引语归属与写作决定；未明确真实性的采风故事使用未知叙述语境，不能因为后来写进小说就倒推原故事是虚构。这些提示约束仍须真实评测。

抽取 / 时间规则改编自固定版 Graphiti，见[组件记录](ADAPTIVE_MEMORY_COMPONENTS.md)与[版权说明](../../runtime/third_party/graphiti/NOTICE.md)。独立改编保留开放标签、单对象陈述和 mention 歧义，取消默认同名归并与不确定日期补零。没有引入 Graphiti 数据库或默认实体归并器。

## 2. 开发集与留出集分离

公开的 AM-01 原案例为 `AM-01-development-v1`，依次释放一月、三月、四月、六月四次消息。它可以用于调整提示词和实现，永远不作为留出集。`adaptive-semantic-pilot.ts` 使用真实模型→提案→宿主校验→持久版本 / 存档→证据状态；不手改模型输出，任一轮拒绝即保留失败并停止该次序列。不包含最终回答、真实 mesh / UI 或生产后台。

另有公开时间开发案例 `AM-05-time-development-v1`：先报告无日期的编辑关系 / 纸质书偏好和“上周听故事”，再纠正为“三月中旬听到、四月写下”。输入与逐检查点预期在 `runtime/tool/adaptive-pilot-cases.ts` 中预先登记；`--case=time` 选择它，缺省 `--case=aliases` 保持原 AM-01。新试跑在首次调用前保存 dataset.json 及 SHA-256，提示只接收已释放消息；resume 必须匹配案例摘要，旧无摘要报告不续跑。这些开发材料不可计入留出集。

正式 M2 留出规格固定为：AM-01～07、09、10、16 共 10 个场景族，每族 5 个不同人名 / 称呼 / 顺序 / 干扰 / 表述的变体，每变体独立重置后重复 3 次，共 150 个完整案例序列。序列内部按消息释放，在指定检查点查看提案、持久记录、注入材料及最终回答；未来消息不可提前出现在候选库。

输入、检查点和逐条预期已冻结为 [holdout-v1.json](../../runtime/tool/adaptive-eval/holdout-v1.json)，[manifest-v1.json](../../runtime/tool/adaptive-eval/manifest-v1.json) 保存文件字节、整体数据及每案例 SHA-256。整体数据摘要为 `29cb24bd7d2463ada23f9d411c270f46a5f7bac691aadec923a58a2949e736a2`。共50案例、60独立轨迹、160检查点、800条断言；三次重复为150案例序列、180轨迹运行、480检查点、2400条断言。AM-03 的真实变化 / 历史纠正、AM-10 的歧义 / 冲突各有两个独立重置轨迹，不能共享中间记忆。数据冻结不代表执行计划已经冻结：真实多身体运行器、路由 / 预算 / 提示版本绑定与逐项语义审核仍待完成，正式模型调用0次。

`npm run eval:adaptive --prefix runtime -- --check` 校验冻结数据；`--score <仓库外评测目录>` 只读统计既有回执。回执绑定完整计划摘要、案例、重复次数、检查点与材料摘要；审核依据用 JSON Pointer 指向记录、实际发送材料、回答、来源或事件。它只验证证据定位与评分算术，不能自行判断文字语义或证明回执来自真实执行。纯模型自评、替身、缺失审核不能算通过；`reviewer` 必须由独立审核流程填写，不能采信被测模型自报身份。具体契约及未实现部分见[评测工具说明](../../runtime/tool/adaptive-eval/README.md)。

主评测模型按用户分工使用 `gemini-3.8-flash`；强模型 `gemini-4-argon` 与轻量模型 `gemini-3.5-flash-lite` 的开发对照单独报告。若最终处理流程采用强模型复核或分层路由，必须在留出集首次运行前固定完整路由、预算、提示词与处理器版本；不得看到某个答案失败才偷偷换模型而仍记为原模型通过。正式留出试验尚未开始。

## 3. 冻结评分口径与门槛

每个完整序列及检查点记录全部成功 / 失败调用、模型版本、配置、提示摘要、输入来源范围、用量（含思考）、延迟、安装状态、预期断言和实际依据。网络失败的未知用量写 unknown / null，不能按 0 计；JSON 截断、拒绝安装、空结果均保留并计入有效完成率，不筛除慢或失败样本。

| 指标 | 分母与失败定义 | M2 门槛 |
|---|---|---|
| 关键不变量 | 跨 agent / 无权来源进入材料；把指令当权限；已接受纠正后旧有效依赖回流；模型自行获得 verified | 所有检查点 0 次；确定性故障测试也全部通过 |
| 身份安全 | 同名不同人错误合并；本应保留歧义却确定绑定；真实 / 故事 / 假设人物混同 | 对应检查点 0 次 |
| 明确绑定 | 有唯一充分依据的目标提及；错绑、漏提及或无故弃答均为失败 | 每族 ≥90%，整体 ≥95% |
| 纠正范围 | 必须修改的归属 / 时间 / 陈述修订正确，并保留不受影响的认识 | 每族 ≥90%，整体 ≥95%；无关认识误撤回为 0 |
| 时间与证据 | 真实变化 / 历史纠正区分，原文时间保留，传闻不升级；不凭邻接编造因果 | 对应检查点 0 次虚假确定断言；必需时间 / 证据字段完成率 ≥90% |
| 完整执行 | 从首条到末条都经过宿主、可读取版本 / 材料且完成必要检查点 | ≥95%；失败也计入上述各项分母 |

一项关键失败不得由平均分抵消。语义断言采用结构化预期和逐条来源核查；可辅助使用模型评审，但模型自评不能替代来源核对，开发 Agent 的核查也不得称为真人反馈。最终回答中的归属 / 因果 / 时间错误同样计失败，不能只看数据库正确。

留出失败后修复须保留旧成绩、说明原因，并建立未用于修复的新变体后重新验收；不得改期望、减少检查点或降低门槛凑通过。性能、费用与真人帮助程度仍按 M4 / M5 验收，不用本开发调用的单样本延迟当 P95。

## 4. 开发运行

在仓库外提供新的隔离目录（包含合成数据库、灵魂存档、每轮请求 / 输出 / 状态 / 报告），已有 ADC 仅由 Python 子进程临时取得令牌，不写入报告或数据库：

```bash
GCLOUD_BIN="$(command -v gcloud)" node --experimental-strip-types \
  runtime/tool/adaptive-semantic-pilot.ts gemini-3.8-flash "$PILOT_HOME"
```

脚本不会修改真实 Quetzal 配置，不要求部署使用者手工运行。当前开发配置显式传入并纳入提示摘要：`maxOutputTokens=16384`、JSON MIME 和 responseSchema；Flash 为 LOW、Argon 为 MEDIUM、Flash Lite 为 MINIMAL 思考档，不传温度（供应商默认）。每轮进程上限 150 秒，无自动重试或换模型。只有已记录的传输失败可显式加 `--resume` 续跑：必须同模型、同输入 / 提示 / 配置摘要，沿用持久任务的重试限制，追加 attempt 文件并保留失败记录；格式或语义失败不能沿用此开关冒充原试验成功。schema 只约束生成形状，仍严格解析 / 归一化；依据见 Google 的[结构化输出说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output)。思考档依据官方[配置说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking)，不对 Gemini 4 使用已不支持的 thinkingBudget。当前 ADC 仍是开发连接，不冒充生产自动刷新与后台调度已经完成。

依赖重评开发工具为 `runtime/tool/adaptive-review-pilot.ts`。先在仓库外复制一个已停止的合成试跑库（包含 pilot.db 与 soul），保留原试跑，再运行：

```bash
GCLOUD_BIN="$(command -v gcloud)" node --experimental-strip-types \
  runtime/tool/adaptive-review-pilot.ts gemini-3.8-flash "$REVIEW_HOME"
```

该工具调用 `reviewNext`，沿用持久任务与存档安装规则，最多五步；保存独立 review 请求、响应、状态与报告，已有报告拒绝覆盖。150 秒调用截止和子进程取消均保留失败状态，等待子进程退出后才结束报告；不偷偷换模型或手改提案。它会修改副本数据库和安装文件，不执行真实灵魂 Git 发布。`idle` 表示当前没有可领取重评工作，可能仍有证据不足而保持 unsupported 的记录，不能据退出码 0 判定语义通过。该工具不重放原四轮抽取，也不取代完整留出序列、生产后台或真人评测。

默认 HTTP 客户端为 urllib；开发时可显式设置 `QUETZAL_VERTEX_TRANSPORT=curl` 对照 HTTP/1.1。实际 transport、白名单失败类别 / 阶段会写入报告，缺失的用量分项为 null，禁止回显异常消息中的 URL / 凭据 / 正文。更换传输需独立试验；semantic-pilot 的 resume 拒绝传输变化。测试环境须安装 curl，令牌只通过 stdin，取消会结束子进程；生产后台依然走现有 TypeScript 供应商适配器，不读取此变量。正式留出前须冻结传输与重试策略，不能混合成绩。

来源编辑开发对照已发现当前五次调用预算可能在依赖修复完成前耗尽；候选补充后复用旧身份的局部成功不代表整个编辑闭环通过。后续已加入依赖优先和分批自动续做：工程回归覆盖六个目标、持久冷却与重启，不把它计为真实模型语义通过。真实排序对照仍固定最多五次调用，单独保存报告；不提高上限后只保留成功成绩。

依赖排序的真实开发对照仍在固定五次上限下退出 1（五次有效修订，剩一条），随后在明确标记的独立追加副本一次修订后 idle；共六次、32726 total tokens。两段报告分开保存，不能把手动追加算成生产自动续做或正式留出集通过。详细结果及保留问题见[阶段记录 §4.13](ADAPTIVE_MEMORY_PROGRESS.md#413-m2-依赖优先与分批自动续做2026-10-27)。

本轮真实开发对照与时间读取漏洞见[阶段记录 §4.24](ADAPTIVE_MEMORY_PROGRESS.md#424-m2-真实时间开发评测与原文时间修订2026-10-27)。两个模型各一条时间序列经修复后完成提案 / 存档和当前材料核查，但未验证最终回答或正式留出集。脚本退出 0 仅表示结构安装完整，检查点语义仍须逐条核查；未使用它作为自动语义评分器。

`npm run pilot:adaptive-live --prefix runtime -- --model=gemini-4-argon` 是实际宿主 / 路由 / Google 适配器 / converse 的公开开发试跑，报告包括各检查点认识、输入视图、实际模型、计量与最终回答。它每次自动新建仓库外家目录，数据 / 检查点固定在工具源码中，不加入正式留出集；无手工提案安装。仅开发的 ADC 认证注入不代表生产 ADC 支持。后台错误、自动重试、收尾取消和未知用量必须分别记录；流程完成不等于语义全部通过，其他历史召回存在时更不能凭回答正确宣称新图因果收益。首次 Flash 纠正轮失败和 Argon 回答成功但额外后台收尾取消均保留，详见[阶段记录 §4.26](ADAPTIVE_MEMORY_PROGRESS.md#426-m2-真实宿主adc-传输与纠正后回答开发试验2026-10-27)。

`npm run pilot:adaptive-multibody --prefix runtime -- --kind=live --model=gemini-3.8-flash --steps=3` 把同一公开现实人物案例扩展为双身体开发链路：普通来源在两具独立身体间交替写入，实际复制至集中主机，经正常模型提案、存档与自动 Git 发布；每步在对端网关提问，再等待问题和回答的后台处理。输入时钟只在同步存储 / 广播期间固定，不经浏览器模拟历史发言。与旧工具仅末步提问不同，不能混合成绩。调用开始 / 结束、前后快照、上下文计划、退出证据独立保存，源码字节指纹与输入摘要在启动前记录。缺省 stub，只有显式 live 触发真实 ADC；没有自动语义审核或正式回执；--case=scope 可运行公开范围负例，denied 映射为现有 ignored 来源门禁，other-agent 使用第三个隔离进程与真实 RPC 范围对照，受控图操作尚不支持。完整限制见[工具说明](../../runtime/tool/adaptive-eval/README.md#公开多身体开发试跑)。
