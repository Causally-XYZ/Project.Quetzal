## 1. 提案接口 v1

`adaptive-proposal.ts` 提供 `proposalPrompt` 和 `normalizeProposal`。模型看到宿主分配的来源 s-key、已有记录 r-key 和语境句柄，输出 `{contexts,records}`，新 / 修订记录使用 p-key；replace 指向待修订的 r-key。宿主生成 UUID、连续版本、来源 hash、精确 UTF-16 引文位置和整体代次。重复制式引文未明确 occurrence 时拒绝，不任意选择第一处。旧版本 / 已失效来源在提示材料中显式不可用，不自动指向最新版本。语境声明仍逐项校验类型、唯一句柄和精确出处；合法但没有记录引用的声明不落库，也不阻止其他独立记录安装。它不放宽实际记录的跨语境引用规则。

模型输出只是提案：格式 / 引用验证、语境隔离、版本安装和原文语义理解是不同层。结构合法的错误理解仍算语义失败。空提案允许表示没有新认识，但不能用普遍弃答掩盖漏提取。既有个人确认规则保持不变。

编辑原文后，输入 `sourceChanges` 列出旧依据失效的记录与可读的新来源句柄；旧引文保持 unavailable，不能自动换 hash。重评同时提供 `review.candidates`，包含同语境已有对象及定义，目标仍只允许修改一条既有记录。对象是检索候选，不是等同身份的结论；同名归并或重复造对象仍计入语义核查。原文删除 / 忽略后的工程隔离与真实语义修订质量分别验证，不能据替身回归认定真实模型通过。

输入额外提供 `dependents`（r-key → 当前精确版本的直接下游 r-key 列表），供模型在同批纠正中检查依赖，而不盲目更新版本引用。开发报告的 `reviewCandidates` 是纠正前快照中传递受影响、但本批未修订的记录引用；它不表示这些记录全部失效，也不能代替待重评任务队列。提示要求拆开可独立纠正的吃饭事件、引语归属与写作决定；未明确真实性的采风故事使用未知叙述语境，不能因为后来写进小说就倒推原故事是虚构。这些提示约束仍须真实评测。

抽取 / 时间规则改编自固定版 Graphiti，见[组件记录](ADAPTIVE_MEMORY_COMPONENTS.md)与[版权说明](../../runtime/third_party/graphiti/NOTICE.md)。独立改编保留开放标签、单对象陈述和 mention 歧义，取消默认同名归并与不确定日期补零。没有引入 Graphiti 数据库或默认实体归并器。

### 六个月虚拟生活开发轨迹

需求方于2026-10-28明确要求。新空库、新人物起步，先固定人物背景、关系、习惯、局限和愿望；不预先安排未来谜题或“必考”纠正。世界 agent 与角色 agent 使用独立历史：世界仅接公共起点、自身事件与角色实际选择的生活行动，追加外生变化和行动结果；角色只接其可感知经历、私人状态及实际产品对话，不得获得隐藏动机或未来真相。Quetzal 仅收到角色实际送达的正常对话；模型模拟不作真人反馈或独立真值裁判。

采用约60个长短不同的1～7日片段覆盖过去六个日历月，可有平静、重复和长期没有提及的生活。最初自主选择使用 / 暂缓 / 不用的先导保留；需求方随后明确改为事件系统掷骰、约30%记录率。当前按到达顺序，每10个可感知事件条目无放回随机抽3个，抽样只用预先固定的种子与序号，不读内容或产品结果；末尾不完整块保留误差，不补抽。条目来自可感知观察及可见行动结果，同片完全相同文本去重，routine只作背景。抽中时角色必须自然表达其核心信息，可合并和省略非核心细节；未抽中时只生活，记录后仍可自然续聊但不新增未抽中事件。实际自然语言是否覆盖核心、是否意外披露其他事件须另核，不能靠schema或抽样数冒称已验证。

人物与世界仍不接产品内部状态；身体和会话按场景选择。为覆盖输入渠道，另预登记每10次实际发送随机分配7次打字、3次语音，角色在表达前获知渠道；噪声随后按原合成规则处理。抽样事件数、实际发送数、渠道和字符扰动是不同分母，不混成“30%用户使用率”。不把未披露事情计为漏记，不从受控频率推断真实用户留存 / 满意度。世界历史追加不代表模型世界必然自洽，矛盾必须记录与审查。

输入噪声在表达形成后处理，只接表达、渠道和输入风格，不看世界账本或产品答案；使用同音误转、分词 / 标点丢失、typo等合成扰动，保留干净意图、送达文本、是否向角色显示转写及后续自然纠正。噪声概率 / 替换是开发参数，不冒称真实ASR分布；不能为凑覆盖强迫每句出错。质量判断同时区分原意、产品实际收到的内容及其有理由知道的范围。

私有测试日历统一人物日期、模型当前时间、消息 recordedAt、会话及相对时间展示和本次检索新近度；真实调用时间、任务租约 / 重试、网络信封新鲜度和取消继续走真实时钟。每次跳日期前等待在途前后台工作结束，同一日内按实际耗时前进；同一人物前5片检查信息 / 时间边界后继续完整轨迹，不重生成较好的开局。新模拟的首次 / 后续调用、成本、跳过、失败与未决发送全部保留；预算是资源上限，触顶明确记未完成，不是逼角色凑轮次。该运行不验证真实半年老化、TTL、真实沉默后的清理、自主昼夜或提醒调度。

编排复用既有身体、网关、持久任务和观察器，控制器 / 人物 / 世界 / 噪声及证据均在仓库外，不新增生产配置、RPC或评分平台。首段时间与信息边界需实测；完整运行与后续语义核读结果另入阶段记录，准备或生成设定不计为完成。

分项中的repair-delay是首次观察时是否已修复，不能当修复毫秒；first-use与repair-delay、second-use与recurrence可能重叠，不累加为独立证据。真正“先正确后复发”须在sequence跨点核读说明，未观察不记为零事件。参考事实不要求每次回答逐项复述，但必须完成当次有依据的关键任务。审核理由与原件继续保留，不能用分项检查通过率冒充自然错误事件率。

使用一个主指标并单列纠正表现：

- **固定分母。** 保留10族、每族5案例、每案例3次独立重置，共150个案例序列。每个案例的多条内部轨迹合并为一票；同一事实多个断言不能重复加分。整体至少143/150、每族至少14/15合格，这是原95% / 90%方向在该票数下的向上取整。另按50个案例报告三次重复的一致性，不声称150种独立问题或总体真实用户准确率。
- **实际帮助。** 合格意味着完成预登记的关键记忆使用任务，有足够依据且没有影响任务的错误归属、时间、因果或持续误导。充分线索下全部弃答、只复述无关内容不合格；本来欠定时明确未知、给有用的条件判断或针对性复核可以合格。局部措辞或不影响任务的偏差单列，不要求每句话零误差。各案例的关键事项须在运行前固定，不能见结果后把错误降为“小处”。
- **纠正与再用。** 对适用案例，在纠正 / 新辨别信息被处理后，穿插一次无关话题，再观察两次相关使用。第一次允许局部修复延迟；第二次仍沿用影响任务的旧错，或首次已正确而第二次复发，该序列不合格。目标仍是自动纠正，不要求用户重复提醒。未再使用记“未验证”，不能当已修复；最后一次才修好也不称已经证明之后稳定。现案例缺少观察点时补入同一序列，新增输入 / 数量及预期在新留出释放前登记，不另加150组。
- **失败与审核。** 未运行、执行失败、未审和材料不足均留在150分母，不计通过；不能通过删难例提高分数。保留每次失败、有限恢复及实际费用，旧v1失败单独可重算。通过需来自逐条来源、实际材料和回答的独立核查，不用被测模型自评或数据库accepted作评分。
- **严格工程边界。** 跨agent / 无权来源进入、原始来源完整性、已登记失效版本阻断、未经授权获得verified等仍要求零故障且证据完整。自然语言漏识别纠正目标与接受过期patch是不同失败，不能整类放宽。原规模、模型对照、部署 / 恢复 / 界面及阶段push要求不变。

这套简化口径允许少量失败，也可能容许失败集中于某种纠正机制。因此同时报告：首次错误、是否有充分辨别信息、修复延迟、首次 / 再次复用、复发、下游扩散、无关认识损失、弃答与帮助；按场景族和错误类型分列，不用总分掩盖。它检验有限轨迹内的恢复，不能证明无限时间收敛。

本次未选择另设“纠正后复用成功率”独立硬门：小分母直接套95%可能变成隐性100%。先采用上述一个主指标与完整分项，不另建评分设施；若分项暴露集中风险，照实提出，不擅自宣称产品安全或已达到真实用户95%。两次复用是本次确认的有限观察窗，不是产品必须等待两次提醒才纠正的行为规则。
