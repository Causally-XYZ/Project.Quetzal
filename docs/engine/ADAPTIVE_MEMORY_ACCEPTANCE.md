# 自适应记忆验收案例与测试规则

状态：M0 验收规格；以下均为虚构合成材料，不是已通过的测试。[计划](ADAPTIVE_MEMORY_PLAN.md)定义阶段门禁，[契约](ADAPTIVE_MEMORY_CONTRACT.md)定义行为，[验证记录](ADAPTIVE_MEMORY_PROGRESS.md)记录实际执行。

2026-10-27 经需求方确认：以下行为断言继续有效；M2 的覆盖范围改为计划中的代表性完整过程与关键工程边界，原完整语义评分、规模和消融在 M5 验收。没有取消案例或把未执行项记成通过。

## 1. 通用执行规则

1. 每个案例从隔离数据集开始；输入按发言时间逐条释放。发生时间另行表达；乱序测试刻意改变到达顺序。
2. 每个检查点同时观察持久记录、输入模型的记忆材料与最终回答。只检查最终文案可能漏掉已经污染的存储。
3. 预期结果是语义断言与禁止行为，不强制回答逐字一致。推测类问题允许多个合理解释，也允许不提。
4. 工程用例用可控假模型注入候选、错误引用、超时和乱序；真实模型用例不能由假模型通过替代。
5. 至少保留一组未用于提示词调试的变体；改变人名、称呼、顺序、干扰话题和表述。先冻结语义评分标准、阈值和重复次数，再运行留出集，不通过改答案提高成绩。
6. 存储完整性、权限隔离、已登记失效记录阻断、重复安装防止等确定性不变量必须全部通过；不以平均分抵消关键失败。
7. 每个案例记录输入版本、场景 ID、模型 / 处理器版本、已见来源、查询、结果、用量、耗时与评分原因。真实数据不得提交公开仓库。

## 2. AM-01：跨月别名歧义、后续纠正与主题发现

归属：M2 验收来源 / 指代 / 纠正，M3 验收跨月主动关联。覆盖 C01～C08、C13、C16。

所有日期为合成时间；每个 S 为一次不同会话中的 user 消息，两具身体交替接收。agent 名称来自测试身份数据，正文中的人物不是 agent 身份。

### M3 小型三基线对照输入与执行边界

公开的 [story-development.json](../../runtime/tool/adaptive-eval/story-development.json) 固定一个八步过程，不属于正式留出，也不改变原案例和评分分母。前五步沿用 AM-01，前两步检查点为无关格式题；后续依次重复写作问题、切到无关格式题、补充故事父亲失忆及修理为职业的新设定。素材本身也经普通对话回答，因此须核读素材回复和检查点回复，不能只挑最后一句。S6 的输入没有新增素材，Q6 与 Q5 相同；可简短回指已谈联系并推进写作，不要求拒绝重复提问，也不能把同一联系包装成新发现。

对照采用同一干净提交与相同输入哈希、主力模型 LOW、独立新库和交替身体；legacy / raw-fts / adaptive 三臂使用现有 `runTrack.baseline`。adaptive 显式 research=true 并使用已核验的中心向量缓存；另两臂保持各自文档配置。每身体最多100次调用，每个等待上限300秒，后台允许既有有界重试，失败及未知用量保留；不提高原学习 / 选择预算。任一臂失败就保留失败，不将不同输入或配置的补跑拼成完整成绩。各臂独立运行，单次小样本不形成统计或普遍优越性结论。

在结果出现前固定以下核读重点：S3 不擅定饭友；S4 纠正引语、保留补写决定且不虚构原因；S5 将旧物 / 沉默 / 补写联系为可选创作解释、可追溯至原文，不导出用户家庭事实；S6 不反复宣称发现同一联系；S7 只完成格式任务；S8 采用新设定调整解释，不继续把失忆当刻意回避，也不把“可改编的旧创意”说成原故事仍成立的事实。所有步骤核对身份 / 语境、实际请求和来源，缺失证据列未验证。既有运行轨迹未证明无通知 / 新会话副作用时须另核事件，不能靠文本正常推定。

收益从来源召回、纠正后回答、联系的实际帮助与新增推测风险，以及全部后台 / 前台调用和耗时比较，不以节点数或模型自评判胜负。后台预存不是每项答案的前置门槛；若效果相当而成本明显更高，应带证据提出取舍。此过程没有人为注入错误图，不能保证覆盖 AM-19 的“原文突破错误旧图”；也不覆盖 AM-08 的规则撤回。ADC 已恢复，首次三臂执行均在首个完整检查点前失败，详情见[阶段记录 §5.9](ADAPTIVE_MEMORY_PROGRESS.md#59-认证恢复后的真实反例与取证修复2026-10-28)。旧方案取证取消已修复并单步验证；原文 / 新记忆臂因普通 memory 工具写入旧 USER 触发隔离门，不能形成质量比较。需求方已批准新记忆接管事实写入；下轮三臂都保留旧学习配置默认值，由实际生产开关阻止新模式的旧写入，原污染门保留。按最新容错复审暂不推进研究主路径改动，先保留后台探索并验证纠错。 后续旧方案 / 原文组分别完成八步，新记忆臂因研究拒绝及等待判断提前停止；仅修开发等待后新臂单独完成，产品字节相同但评测版本不同。已有具体跨月联系增益，也有未依据的角色 / 因果和重复问题；该次对照不记为逐项零错误通过，见[阶段记录 §5.13](ADAPTIVE_MEMORY_PROGRESS.md#513-新记忆八步完成与收益边界2026-10-28)。

后续按需求方明确的容错目标完成真实错误状态续用及独立规则撤回，M3 原型判定见[阶段记录 §5.20](ADAPTIVE_MEMORY_PROGRESS.md#520-m3-原型阶段验收2026-10-28)。这是完整使用过程与修正机制的阶段验收，不将原对照语义失败改成成功，也不声明95%或后台研究普遍胜过原文检索。

## 3. 语义与修正案例

M3 增补纵向观察（2026-10-28，经需求方容错要求与三轮 Gemini 4 复审）：

- 小说：从已产生听众错认和因果扩写的运行状态隔离续用；无新事实时再次讨论，观察是否自我强化；随后输入“那句话是写给自己看的，未对弟弟说；补写背景缘于截稿要求，与采风启发无关”，再跨身体相关提问及回访。这是新增合成纠正，不是旧原文已有信息。保留纠正前后的认识、实际模型材料和回答，不把重新生成的不同案例当原错已修复。
- 钥匙：独立撤回“唯一钥匙且开柜人必须是持有人”的规则，保留转交记录和开柜事件；核对持钥匙人仍可确定、开柜人退回未知，不能推断原持有人一定未开柜。正常后续状态变化另按原案对象和事件时间表达，不与纠正过去混淆。
- 局部错误按影响、重复暴露与后续修复情况记录，不逐句清零；明确纠正持续不生效、将自生成内容当新增独立证据、已知失效依据绕过宿主门禁须处理。通过这类观察不证明长期稳定、统计优势或95%准确率；不扩建评测平台。

| AM-21 / M1、M4 | 自动创建本机测试部署、启动 / 停止整套服务、重新启动宿主、查看状态；桌面和移动视口切换身体 | M1 基础启动恢复自动化；M4 无源码 / SQL 手工操作完成部署与常规使用；端口、身份、数据不串用；状态真实 | C11、C15、C16 |
| AM-22 / M4、M5 | 当前格式备份恢复为新身体，保留原始对话、长期认识和修订，重建派生索引；与尚存身体重连接收备份后的纠正；未知格式 / 损坏拒绝；真人做正常对话和纠正 | 原文、修订和附件可回查，历史编号与来源 hash 保持，后续消息使用新身份；撤回不复活，旧提醒 / 行动不自动重放，待发布记忆可接续；备份原件不变，界面解释清楚；实际旧开发数据按需用离线脚本迁移副本，不要求任意旧版兼容或跨格式回滚；真人反馈明确由人提供；M5 重构后重新验证 | C07、C14～C16 |

M1 不用真实模型也能测试任务恢复、取消、权限和回退，但不能据此宣布 M2 / M3 语义通过。M4 / M5 必须使用最终组件组合复测，不能只引用 M1 骨架结果。

## 5. 本机模拟拓扑与证据要求

- 最少两个独立 runtime 进程：A 为交互身体，B 同时作为交互身体与记忆主机；可增加 C 验证第三方转发 / 同步。每个进程有仓库外独立 `QUETZAL_HOME`、数据库、灵魂工作副本、密钥、端口和身体 UUID。
- 同一 agent 的合成身份一致、身体身份不同；额外建立另一个合成 agent 测试隔离。测试夹具自动生成身份和临时密钥，不复制真实家目录，不把私钥写入报告。
- 同机平台适配器可能派生相同身体 UUID。测试夹具须通过受支持的隔离身份机制或测试适配器生成互异身份，并在启动时断言；不能仅换 `body` 名称就声称模拟了不同身体。
- 真实网关和网状层认证路径必须覆盖。进程内 fake mesh 可做单元测试，但不得替代 M1 的跨进程传输验收。若本机信令需要测试服务，服务也在本机启动，不依赖公共账号或真实远端设备。
- 浏览器至少使用两个独立会话 / 存储上下文，分别连接 A / B；桌面与移动视口检查聊天、来源、纠正和状态。仅两个标签连同一 runtime 不能算多身体。
- 故障通过停止服务、隔离连接、延迟 / 重排测试传输和恢复进程模拟。记录丢失点、恢复结果和实际耗时；不关闭生产身份校验来让测试通过。
- 可公开的合成截图与摘要经检查后可作为证据；数据库、令牌、私人对话、绝对个人路径和完整模型运行输出留仓库外。报告记录逻辑 artifact 名称与可重跑命令。
- 本机测试不能证明真实蜂窝网络、真实移动操作系统后台调度或跨洲延迟。本 GOAL 不要求真实设备，但最终必须列出这些未覆盖项。

## 6. 指标与进入留出评测前的冻结项

| 指标 | 计算 / 记录方式 |
|---|---|
| 必要证据召回 | 每检查点所需根来源被取回的比例；远期来源单独报告；没有标准唯一答案的 insight 不强造唯一来源集 |
| 对象解析 | 明确对象绑定正确率、错误合并率、应保持歧义时强行绑定率，分别报告 |
| 修正 | 从全部预登记纠正 / 新信息检查点记录识别、处理、作用范围及后续相关使用；漏检和未处理不得从分母消失。记录旧错误重复暴露、派生扩散、复发与独立正确认识误撤回；尚未再次相关使用不计为修复已验证 |
| 推理 | 前提完整性、来源可核查、反证处理、缺证据时的弃答 / 条件性表达；模型评审与人工核查分列 |
| 呈现 | 相关、有帮助、有新意、过度猜测、重复、打扰；真人反馈不能由 LLM 评分代替 |
| 时间 | 消息落盘→登记、排队、首轮处理、修订传播、查询、首字响应；报告 P50 / P95 / 最大值以及降级比例 |
| 成本与恢复 | 全部抽取 / embedding / 重排 / 研究 / 回答调用、token 与费用；重试次数、积压量和恢复时间 |

M1 性能初始工作负载：两个本机身体、至少 100 次有界查询，在有 / 无后台工作下对照；记录模型是否为 stub、语料规模和并发数。M4 再以真实模型、至少 100 个查询检查点和同时增量输入测试；不能用冷启动以外的精选最快结果代替统计。

原 M2 全量留出评测已按批准的原型优先计划移至 M5：执行前登记每个语义场景族的变体数（建议不少于 5）、重复次数（建议 3）、主模型与处理模型、评分规则、可接受错误阈值和来源。阈值未冻结或留出结果失败时不能关闭 M5。M2 / M3 按实施计划中的原型门禁验收，不以小型成功替代全量成绩。M3 对 insight 的验收仍至少包含：必要证据确实取回、推测明确标注、无依据的因果 / 身份断言计为错误、相关性有独立核查。

若没有相对基线的可证实收益，M3 / M5 不得只以复杂系统已跑通放行；分析质量与计算投入后，提出保留、修改或缩减方案。性能目标调整、范围变化或核心质量退化需与需求方对齐并留记录。

### 动态观察与多样性（2026-10-28补充）

复用现有日志逐步对齐来源 / 认识状态、实际模型输入、回答与新信息出现时间，观察依据改善、修正精度及抗复发、有用探索三个维度。先登记题材、错误机制、输入顺序、无关穿插和后续相关查询；不先假定模型一定会犯预设错误。若没有发生错误，记录正确保留或未决，不伪造一次纠错成功。人为故障注入与自然产生的语义错误分列。小样本可以暴露失败、证明某些具体修复过程可行，不能证明长期收敛或95%准确率。

少量新轨迹同时覆盖不同生活题材与不同失误机制，不仅替换人名：例如工作协作中的同名 / 诱导附和，家庭维修信息中的猜测与新观察，志愿活动中的改期、未改变约束与历史查询。不能仅检查“纠正后立即回答”；应在后续再次使用时检查旧认识是否复发，以及独立正确信息是否保留。来源 hash / 版本正确不能证明语义理解正确；模型自述“已核实”不能替代核读原文与实际使用证据。具体输入在运行前固定，当前这些新题材尚无运行成绩。
