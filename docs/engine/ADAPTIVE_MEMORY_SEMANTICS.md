# 自适应记忆：认识版本与证据依赖

状态：M2 阶段内的存储 / 计算库与受控后台试验，已有合成工程测试及独立真实模型开发调用；默认关闭的宿主后台已接线，集中主机本机的前台认识查询已接入，远端查询已接入版本冲突核查，完整验收未完成。不是 M2 放行记录。目标见[行为契约](ADAPTIVE_MEMORY_CONTRACT.md)，结果传输与发布见[存储协议](ADAPTIVE_MEMORY_STORAGE.md)，实际测试见[阶段记录](ADAPTIVE_MEMORY_PROGRESS.md)。

## 1. 为什么把这些规则留在宿主

模型负责提出“这句话可能指谁”“哪些证据共同支持这条认识”“新话纠正了什么”。宿主负责身份、版本、精确出处、事务、依赖计算和访问过滤。格式正确不能证明模型读懂了原文，也不能证明推论逻辑有效；后者必须通过真实语义评测。

实现入口为 `runtime/src/memory/adaptive-evidence.ts`、`adaptive-graph.ts` 与权威存档入口 `adaptive-archive.ts`。提案层已改编固定版 Graphiti 的抽取 / 时间提示规则，保留许可证与修改说明；[组件实验](ADAPTIVE_MEMORY_COMPONENTS.md)仍不等于完整上游服务集成。

## 2. 最小记录

新信封 `payload.schema` 为 `quetzal-adaptive-semantic-v2`（读取仍兼容没有 references 的 v1），`data` 为 `{baseGeneration, records}`。一个批次 1～100 条记录；每条记录共有宿主 UUID v4、连续递增 `revision`、`present / withdrawn`、`realm` 和审计出处 `reasons`。拒绝未知字段，不接受模型自行写入 `active` 或 `verified`。

| 记录 | 主要字段 | 含义 |
|---|---|---|
| node | name、labels | 同名可有多个对象；标签开放，不预设职业、家庭或创作主题树 |
| mention | anchor、candidates、unknown、resolved | 具体的一次提及；候选引用对象的具体版本，允许未知、多个候选和未解歧 |
| claim | text、nature、participants、references、occurred、valid、supports、counters | 有来源的陈述 / 推论 / 假设；参与者经 mention 引用，支持与反证分别成组 |

`realm={world,context}`：world 为 real / fiction / hypothetical / unknown；context 是宿主维护的语境标识，不用模型随意拼写的标签当世界身份。提案由模型识别语境、宿主分配标识。需求方已于 2026-10-27 确认允许有来源的明确跨语境谈论 / 创作 / 引用关系，身份与事实依据仍严格隔离（行为契约 C04）。v2 将关系指向放在 claim.references（可省略，等于空数组），格式为 `{role,mention}`；role 开放，mention 必须引用具体版本的提及。references 可以跨语境，participants 与支持 / 反证仍要求同语境。node 的 realm 不允许在同一 ID 的修订中改变；重新解释身份需要独立对象和明确修订，不能靠改 realm 把角色变成现实亲属。不同语境的对象不能直接互相代入；跨语境比较应另行明确表达，不能靠复用同名节点暗中连接。

references 只接受 mention，不能直接放 node 或 claim；提及的候选 / resolved 对象仍须属于提及自身语境。查询保留引用角色、名称、语境和版本；原文修订视图保留当前引用的角色、语境与名称，并标明关系自身的修订版本。关系要有自己成立的支持组，且其全部参与者和被引用提及均有当前、可访问且解歧的绑定；仅有 references 而没有 supports 不成立。被引用对象的身份来源参与读取完整性核查，不把该世界的其他 claim 当作事实证明。引用目标被纠正后，旧版本关系立即退出当前结果，需有依据的关系修订才能恢复，不自动换名字。

这些是结构与版本保证；原文到底在叙述事实还是引用故事、提案的 realm 及指向是否准确仍由 LLM 提议并经真实语义评测，宿主不能仅凭合法 JSON 证明语言理解正确。不能用新建同名节点或把故事文字直接标成现实陈述来规避契约。

新批次使用外层 result-v2；新读取器兼容 result-v1 / semantic-v1 的原始历史，不重写旧文件或哈希。v1 语义批次携带 references、新语义藏在 result-v1、未知外层版本均拒绝。旧读取器遇到 result-v2 在解析入口失败，不能跳过新结果后使用旧投影。SQLite 投影 schema 2 与灵魂规范 v14 的 Markdown 目录不变；混合版本的全套部署 / 回滚仍须 M4 验收。

出处为 `{kind:'source',source,hash,start,end,quote}`，位置按 JavaScript UTF-16 偏移，必须与当前来源 hash、原文切片完全一致，边界不得劈开代理对。模型端未来可提供原文引用，但最终位置应由宿主对齐；重复引文不能任意挑选。目前已有 `adaptive-proposal.ts` 规范化器，严格检查重复引文定位、宿主 ID / 版本和当前句柄，见[评测与提案接口](ADAPTIVE_MEMORY_EVAL.md)。

记录引用为 `{kind,id,revision}`，不能只指向“最新”。一句话可以有多个 mention，也可以为多条 claim、多组依据提供材料；本批不把一句话限制到一个主题。对象名称、标签和文字内容本身都不是充分证据。

`occurred` 与 `valid` 均保存 `{text,earliest,latest}`：保留原文时间描述，无法确定时边界为 null。确定边界使用 UTC ISO 时间；日期倒置、非法日期和无原文描述却填时间被拒绝。消息时间保持在原始消息里，处理时间在结果信封里，均不覆盖事件时间。提示和响应 schema 明确 recordedAt 不作为事件 / 生效时间的缺省值；没有表述则 text 空、界限 null，模糊时期或时区不足不补出精确 UTC。时间语义仍由真实模型评测，不由格式校验保证。原文修订覆盖层对当前 supported claim 完整携带 occurred / valid，即使正文相同也能表达仅时间变化；来源不可见时仍不输出 current。

## 3. 支持、反证与循环

支持和反证都用 `{id,premises,assumptions}` 组成依据组。组内前提是 AND，不同支持组是 OR；前提可为精确原文或具体 mention / claim 版本。node 不能直接充当推论依据。`reasons` 是版本变动的审计来源，不被暗中追加为 claim 的必要前提，否则会把独立依据的 OR 错变成全局 AND。

一个无附加假设的反证组全部成立时，阻断该 claim 和依赖它的下游。反证也绑定版本：反证本身被撤回或纠正后，旧版本引用不能继续有效。有附加假设的反证留作候选，不作为确定阻断。

计算先求正向最小闭包，再交替收紧反证假设下的上下界；不按记录排列次序裁决相互反驳。没有独立根的正向循环不能自证；有根时传播依据，根集合按来源 ID 与 hash 去重，同一发言重复加工不会变成多份独立证据。来源角色只有 user / ambient 可作为当前库的独立根，agent 自己的重复陈述不增信；外部工具证据如何准入仍待实现，不偷换成用户确认。

| 状态 | 当前含义 |
|---|---|
| supported | 有当前有效的支持组和参与者绑定，且没有未决 / 成立的反证阻断 |
| ambiguous | 该次提及保留歧义，未解决指向 |
| conditional | 必要前提当前可用，但仍有显式附加假设 |
| contested | 已有成立的反证组 |
| indeterminate | 反证循环等导致上下界未能确定 |
| unsupported | 缺少当前完整依据，包括失效的旧版本引用 |
| withdrawn | 当前版本已撤回 |

这些是依据状态，不是真值概率或个人确认状态。`supported` 不把 inferred / hypothesis 改成 reported，更不升级旧记忆系统的 active / verified。自然语言里的条件蕴含是否成立、反证是否真的反驳，依然需要语义评测；本库不是通用定理证明器。

`unsupported` 或查询零命中不能推出命题为假。普通对话的系统政策与后台提案提示均区分缺少证据和明确否定；否定保留来源及时间范围，之后状态变化不抹去先前有效的否定。普通对话规则不依赖新记忆是否启用或命中，也不依赖当前候选模型。此为提示约束，未增加真值判定器；主力模型公开对照仍出现错误，不能声称已保证回答正确，见[阶段记录 §4.35](ADAPTIVE_MEMORY_PROGRESS.md#435-m2-未知与否定的证据边界2026-10-27)。

## 4. 纠正、事务和读取

正常对话的新回答在 messages.answerBasis 保存消息来源凭据（version 1）：agent、回答正文摘要、consistent、最多1000项来源 ID / 原文 hash / 当前局部修订摘要。凭据与回答同次写入，随现有消息复制；不进入灵魂 Git，不含原文或密钥。来源来自实际模型准备期间的历史、跨会话近况、认识根来源及已核查工具的消息依赖，允许保守包含未最终选入的候选；没有逐句因果映射，不把 unchanged 解释为回答正确。

后续读取在同一快照展开旧回答的来源依赖，包括经过另一条回答继承的来源；本机 generation 不参与跨身体比较。来源编辑、忽略、缺失、认识修订或生成中混合版本使其 changed。默认历史、跨会话近况、context_read 和 recall 不输出 changed 回答的旧正文，保留当前修订说明；原始数据库 / 控制台历史不改写。摘要版本键包含展开后的依赖，防止旧摘要复活。缺失凭据的旧回答明确 unbound，不能追溯补造；文件、外部工具、项目 / Canvas 等其他派生依赖尚未完整绑定，因此不是 C07 全部完成。

数据库启动自动补可空列及非空凭据索引。仅收到凭据、尚无认识文件且后台关闭的新身体也启用读取核查；检测使用部分索引，避免每次扫描全部消息。复制接收核对格式、大小、角色及正文摘要；旧身体可以忽略新字段，新版读取此类副本时降为 unbound，不能宣称混合旧版集群满足本门禁。后来从新版收到完全相同的原消息时可以补入空凭据，已有凭据不覆盖。来源展开仍受1000项 / 256 KiB / 既有500ms快照截止约束；多步累计超限或版本混合保留 consistent=false，不截断后宣称有效。停止后台不会绕过本机已存在认识的读取核查。

纠正保留同一记录 ID，新增版本。被修改的 mention / claim 使旧版本依赖立即失效；不会将所有历史昵称全局替换。某个 claim 的一个支持组失效时，其他独立充分组仍可使用，无关 claim 不连带撤回。下游重推需要新批次，不能只把引用版本改成最新而保留原结论。

`dependentRecords` 在纠正前的快照上，以被替代的具体版本为起点计算传递影响，覆盖对象候选、参与者、支持与反证引用；循环去重，默认 100000 步上限，超限抛错，不交付不完整清单。已撤回记录不作为待修复节点。返回的是需要检查的下游，不是撤回命令：有其他独立依据的认识仍可 supported。开发提案输入提供当前精确版本的直接下游句柄，要求模型重新核对原文与纠正；开发报告保留未被本批修订的受影响候选。

`adaptive-review.ts` 现提供内部重评执行入口：从存档发现 present 记录的旧版本 / 已撤回依赖，以及精确来源已经变化的记录。沿目标和闭包记录的当前及历史版本发现依赖身份，取这些依赖的当前版本与纠正来源，并补入同语境、有可读来源的已有对象及定义，避免旧闭包只含错误绑定而迫使模型新造对象；名称相同仍不能自动合并。 历史版本只用于发现依赖，不把旧记录重新当作当前证据：例如 K 的 G1 已因 A 撤回而移除，后来 G2 的 C 再撤回，仍须给出 A 的当前撤回与来源，不能只给模型最初的 A / B 规则。当前 / 历史闭包合计最多100条记录与100个来源；每计划最多1000个历史版本、100000次引用，超过或缺失来源则明确延后，不能截掉纠正继续调用。历史身份遍历按 ID 去重，任务键包含所选当前版本及来源；历史边本身不恢复支持，也不加入实际调度依赖。以目标、闭包 / 候选版本和来源 hash 生成稳定任务键，通过现有 `AdaptiveStore.scheduleSource` 定向入队。纠正提交与任务发现之间即使崩溃，下次扫描仍能重建工作；任务的租约、退避、五次尝试上限和取消沿用 M1。只有无关整图代次改变不生成重复任务，候选或来源真的变化可以触发新检查。每次只重评一个目标，允许新增必要记录，不允许借重评修改其他既有认识。扫描沿真实记录引用优先上游，补充的候选对象不会凭空产生调度依赖；上游退避或额度不足时延后其下游，独立分支仍可推进。引用环内不存在拓扑序，按稳定 ID 遍历打破排序环，仍受版本门禁、证据计算和目标额度约束，不能凭顺序恢复证明。

调用前后使用宿主提供的灵魂 exclusive，模型等待期间释放锁。新认识批次仍经过 archive.accept；空提案也经 archive.complete，在同一任务完成事务内核对整图 generation 和全部输入修订 / hash。空提案只代表本次无合理修改，不使 unsupported 变成 supported；依赖后来发生变化可产生新的任务。用户取消、急停、关闭、超时和迟到响应均不得安装。下一层因上游修订出现旧引用时会被后续扫描发现，不机械批量换版本。

当前原型扫描上限为 1000 条当前记录，每个依赖闭包连同对象候选至多 100 条记录 / 100 个来源、256 KiB 提示；目标所需来源缺失 / 忽略 / 改为助手发言，或超过上限时显式 deferred，不能伪造完成。来源可读但 hash 变化时可以重评，旧引文标为 unavailable，模型必须重新提供当前原文的精确引用才可修订；不能把旧 hash 换成新 hash 后沿用旧结论。它还不覆盖没有显式依赖的新关联发现。开发执行器至多连续运行五步；生产后台采用分批冷却自动续做，已有工程回归，但真实长链语义质量、大历史候选选择及状态界面仍待完成。因此不是完整生产纠正闭环。

原文读取覆盖层 `adaptive-reading.ts` 现在根据全部已知版本计算每条来源的修订提示：旧依据按精确历史 revision 追踪，保留旧 hash / UTF-16 片段位置；当前来源已编辑时不能把旧偏移套到新正文。提示针对某条认识，不删除原文，也不撤回同段的独立认识。只有可见与全局依据均支持时附上当前内容 / 性质 / 语境及可见根来源 ID / hash；隐藏纠正或反证不会因可见子图单独成立而恢复旧结论，也不返回隐藏正文。

对于有直接原文支持的 reported 陈述，若整条状态为 unsupported、没有 counter，且唯一已检查到的绑定缺口是部分 mention 未解，来源 notice 可附 `identityGap`：直接支持引文及逐角色的 mention / anchor / realm / binding。来源、审计理由、身份与精确版本必须在可见及全局视图同时有效；没有共同的无假设直接支持组、参与身份引用过时、相关身份 / 审计来源不可见或存在反证时不作此解释；不为仅有间接证明的陈述推断失败原因。header 将这些条目表述为“身份关联未完整”，保留已知角色与未知项，reference 仍是被谈论对象。持久图及 notice.status 仍为 unsupported、current 仍为 null，不参与下游证明或拓宽语义索引。新增派生字段进入既有读取摘要；升级时相关旧回答凭据可能保守失效，原文与原回答存档不改。

实际 `context_read` 经 `contextReadChecked` 在灵魂 exclusive 和同一 SQLite 快照中读取当前原文与修订；每页都带提示，offset / limit 只定位原文，不能翻页绕过状态。`recall` 的命中和前后邻句同样核对，忽略来源会被过滤，候选在等锁期间改变则要求重新检索。没有可解析消息来源的旧缓存 / 文档仅提示无法逐项核对，不据此宣称其内容已完成语义纠正。

读取只承诺本机已收到的快照，不声称中心最新。后台未启动或新功能关闭后，只要本机仍有认识存档目录 / 投影见证，这两个工具仍执行修订核对；只有没有任何此类状态且功能未启用时才保留旧输出路径。归档损坏或来源不可访问不能退回旧缓存正文。修订阶段含等锁的截止为 500 毫秒，超时后排队回调不再执行；同步扫描另在返回前核对耗时，**不能据此声称同步扫描不会阻塞事件循环**，真实负载性能仍待测。至多 1000 个请求来源、1000 个当前对象、10000 个版本、100000 步追溯，修订结果 256 KiB、格式化召回 512 KiB 上限，超限拒绝完整结果。

默认历史视图也核对当前原文与修订，不改调用者轨迹；来源编辑后重建带角色 / 时间的资料，忽略或删除后只留占位，旧图像不沿用。自动摘要在本机计划保存来源 ID 和核查摘要值；只有全部被压缩条目绑定消息来源时才写凭据。无凭据 / 版本变化就不继承，历史与旧摘要来源并集超过1000条时放弃旧摘要，不无限增长依赖。窗口准备前后核对，变化清除摘要缓存并最多重建一次，连续变化拒绝本次请求。手动 session_compact 摘要没有来源版本，只作存档，不再截断最多1000条可用原文。全局 generation 变化也会保守使摘要失效，尚未优化为局部增量。

旧结构化候选由 `adaptive-material.ts` 在主模型准备前后与历史同快照核对：只识别 evidence.ref 中精确 message:<id>，不扫描正文猜来源；重读当前受管文件 / legacy 文件，文件已变则拒绝旧候选。命中旧选择缓存仍重新核对。可访问材料附相关局部修订，不用当前消息存在证明旧断言仍成立；任一消息出处不可访问时，因旧格式无逐句来源映射，不输出整条派生正文及证据引语，保留管理元数据。原 state / validation 不改写，读取另有 historical / unverifiable / unavailable 状态。

实际 memory_records 同样核查。note_read 识别受管结构化记录并检查会话范围、实际文件别名；认识批次核对权威文件和全部输入后才输出带修订的历史存档，任一输入不可访问则隐藏 payload。普通无出处 Markdown 不猜引用，仍返回带未核实说明的原文；普通笔记中的格式示例不会仅因出现格式标记就成为受管记录。受管格式损坏不能退回普通正文。单笔记读取256 KiB、格式化结果 / 旧记录列表512 KiB上限。

recall 文档命中复用 prepareNoteReading / 快照 render，先按当前会话范围和来源可访问性过滤，再取请求数量；笔记受管内容不使用索引旧片段，而是输出完整读取视图。普通笔记片段必须对应当前完整正文，日记 / 常驻条目也按来源和正文 / 标题核对；变动时要求重新检索，不返回混合版本。候选最多200项，来源 / 图 / 截止 / 输出上限保留，不能据此声称海量历史全召回。

旧语义选择模型在有界候选正文之外接收完整 reading 字段，不发送不可访问正文，也不接受模型猜回未发送的key。缓存保存全部参与选择候选的来源核查摘要值；同状态复用，来源hash或认识变化重选。模型等待期间变化时丢弃该选择结果，不入缓存；词面降级和关闭旧语义选择器时仍核查来源访问。主模型发送前的核查继续保留。

系统提示的跨会话近况现由 systemMessage 保留对象绑定，每次准备捕获至多五会话各四条消息，取原文与修订的同一快照；等锁期间候选改变则拒绝，摘要期间变化最多重建一次。原文节选最多160字符，修订头完整，4000字符局部预算按整项保留或略过，并提示 recall；不截断修订后保留旧正文。来源忽略 / 删除不展示，旧手动摘要只提示回查。实时输入与草稿尚未绑定持久来源，只呈现运行状态。quick 内省经模型准备钩子对每个候选 / 故障转移重新核查。系统资料参与本轮准备摘要值，但不混入仅由本会话历史生成的持久摘要凭据。

这仍未覆盖任意无出处的系统派生资料（目标、Canvas 等）；本轮四类记忆读取工具现有持久来源凭据与当前投影（详见[工具读取视图](DYNAMIC_CONTEXT.md)），历史过程副本已改为索引并经核查入口回读，外部工具、当轮模型中途文字和学习轨迹仍未覆盖。semantic=true 时集中主机本机使用下述认识查询，原 M1 网络查询仍 unavailable；关闭功能后其他旧路径的全局一致性也仍待补齐。不得把本段标为 C07 全项通过，或把非中心配置的单进程工具测试当成实际多身体同步验收。

SQLite 可选投影保存 meta（格式版本 2、整体 generation）、batches（结果 ID / 摘要 / 代次）和 records（记录 ID / revision / 文档 / 结果 ID）。初始化失败整体回滚；未知版本或损坏元数据拒读。投影 schema 1 原子迁移到 2，记录的外键从本机发件箱改为结果批次表，使另一具身体无需伪造本机任务 / 发件箱即可重建。该版本独立于 M1 队列 schema 2，也不改变灵魂规范 v14。

`AdaptiveGraph.accept` 在已有任务接受事务内校验全部来源与递归依赖输入。批次 baseGeneration 必须等于当前 generation，每条版本必须连续，当前引用须存在；身份候选、participants、支持 / 反证须同语境，只有显式 references 的对象指向可跨语境；允许撤回记录保留实际存在的历史引用用于审计。发件箱、记录、代次、处理回执和任务完成同时提交，安装返回 false 或抛异常都整体回滚。整体代次 CAS 较保守，可能拒绝本来互不冲突的并发批次；先保正确，后续按冲突率决定是否细化。

读取使用 SQLite savepoint 快照，一次计算缓存来源，避免跨连接更新造成同轮混合版本。默认工作上限 100000 个计算步骤；超限抛错，不能把半算结果当成有效证据。当前全图读取尚未做大历史性能验收；本机受控查询已复用此入口，不据此承诺生产前台延迟。

可见结果同时满足全局依据和调用者可访问依据：隐藏的已知反证不能因为权限过滤而让错误结论复活。有其他可访问的独立支持组时可以保留结论，但只返回有效支持组，不泄露隐藏来源的反证 / 审计正文。现有读取器是内部接口，生产权限上下文仍须接线，不能让调用方任意指定来源读取函数。

### 前台认识查询

`adaptive-query.ts` 复用 evaluateEvidence 与 engine 现有词面排序，查询不调用 LLM、不安装新认识。至多1000条当前记录，逐条计算可见与全局状态；claim 先要求两边均 supported，再保留双方共同有效的记录 / 支持组并重新计算证据闭包，仍 supported 才进入候选。两边分别依赖不同分支成立、却不存在共同证明时不能返回该认识或用它支持下游。有独立共同支持的其他分支保留。输出 nature、occurred / valid、已解歧参与者的具体版本 / 名字、共同闭包中有效的支持组与根来源 ID / hash。已失效依据组不随其他独立支持返回，隐藏反证不能使结论复活。mention 只有两边均 ambiguous 且原提及可读时返回歧义、未知标记和可见候选；不会从一个剩余可见候选强行选定对象。未决提及的 roots 仅指其原文锚点，不表示候选身份已获证明。

查询以认识正文、参与者名字和共同有效支持链的精确原文引文排名；模型换一种语言改写时，来源中的词仍可匹配。沿精确版本的 claim / mention 支持前提有界遍历，mention 只取原文锚点；不索引整条消息、审计 reasons、反证、条件或失效分支。引文按来源 hash / 位置去重，循环不重复扩展；额外遍历最多100000步、每候选引文64 KiB、整次引文4 MiB，超限报错降级，不返回半份索引结果。返回正文仍为当前认识，不以原文旧说法替换当前纠正，不增加 RPC 字段；派生向量缓存见本节末。

不把事件时间当作记录新鲜度加权。至多返回6条完整材料，每项最多100个根来源，结果256 KiB上限；超限报错，不截断后伪装完整证据。matched 记录命中数。缺本机组件时仍为词面召回；已准备的中心可补充绑定当前候选的 E5 近邻。这是候选召回，不是开放主题发现或语义判真。空查询不任意挑认识，条件、争议、撤回记录暂不作为本入口的当前材料，历史问题仍走带修订的原文回查。

`queryAdaptiveSemantic` 只在功能开启、semantic=true、服务已启动时读取；指定主机读本机存档，其他正式身体经独立语义方法请求主机。与原文读取共用灵魂 exclusive / SQLite savepoint / 含等锁的500毫秒截止，先核对权威存档。错误或超限返回空 unavailable，用户取消继续传播，急停 / 关闭分别降级。新增 mesh 方法 `memory.adaptive.semantic.query` 发送独立 version 2 信封，接收器兼容不带 references 的 version 1，不将 M1 原文 packet 伪装成认识结果。

`mind/context.ts` 在每个候选模型准备前查询，按窗口选择完整认识，明确 supported 不是事实确认，推论 / 假设必须标注推测，歧义不能擅自选对象，也不产生通知。发送前再次查询；选择内容或代次变化时清摘要缓存并至多重建一次，持续变化拒绝过期请求。不是所有路径已经完成 C07，也未验证真实模型一定遵循这些提示。默认开关仍关闭；全图文件核对与同步计算的实际前台成本、真实语义与真人试用仍须验收。

### 身体间语义结果与本机修订冲突

语义查询信封另带 agent、指定 host、本次查询摘要、生成时间和完整的认识 / 来源版本摘要。前台选择至多6条，但版本摘要覆盖当前图（各至多1000条认识 / 来源），用于保守发现本机比主机更新或有分叉；不返回其他认识正文。解码器严格校验每个字段、来源 / 记录引用、性质、时间、状态、数量及512 KiB上限；不接收 active / verified 或额外字段。正式身体认证继续由 Mesh 提供，只读灵魂桥未获新方法。

接收身体持灵魂锁核对本机权威存档。主机没有本机已有记录、revision 较旧或同 revision 内容摘要不同时拒绝整包；只比较全图 generation 不足以发现同代分叉。主机可读的来源必须在本机存在且当前 hash 相同，尚未复制 / 已删除 / ignored / 已编辑均不允许沿用远端结果。来源缺失与删除不可仅凭行不存在区分，所以必须等待来源复制而不能猜测仍可访问。主机较新版本可用，但不会宣称全网最新。这个保守规则可能因无关分支冲突暂时放弃全部认识，后续再做局部最小依赖优化。

请求网络与接收端核查共用500毫秒截止，用户取消传播；不缓存上次 ready，主机离线或旧版本不认识新方法时空降级，正常对话仍可继续。主模型准备前后都重新走上述路径，生成时间不参与选择相等比较。独立进程测试覆盖真实认证传输、另一身体主模型选入、落后主机 / 编辑 / 忽略 / 删除、补齐后恢复、只读桥拒绝和主机强杀；补齐权威文件由测试故障注入，不替代自动 Git 传播验收。认识提案为合成安装，不代表真实语义质量通过。

### 返回前的消息来源核对

宿主模型—工具循环在供应商返回后核对已准备上下文累计的消息来源；已知纠正、原文修改 / 排除、混合版本或不可核查状态不能直接转成最终文字和该结果中的工具执行。正常 converse 在回复落盘前再检查全轮来源，覆盖结果返回后等待发布期间的修订。无关新增不改变原来源凭据，不因整库代次改变而误拒绝。

最终核对复用权威存档、来源可见性、SQLite 读取快照及灵魂 exclusive。先做预算 / 取消检查并释放只读 SAVEPOINT，再在同一同步临界区插入消息及发 done；没有核对后再 await 的窗口。等锁取消或超时后，排队回调不再提交。提交回调发生错误，不对已经释放的读取 SAVEPOINT 再做回滚。已有500毫秒读取截止和同步扫描不能抢占的限制不变。

正常 converse 遇到来源变化时自动尝试一次只读答复恢复。保留原始消息对象及有持久来源绑定的真实补充，使原文仍可按当前版本重建；当轮模型叙述、工具协议轨迹、工具引入的无出处图片和生成提醒不复制。新 context 不继承旧派生摘要、工作状态或时间线，清除旧累计回答凭据后按实际读取重新收集；原始历史和工具存档不改写。

恢复只提供 recall / note_read / memory_records / context_read，执行端也明确拒绝其他工具，不能靠模型返回未列出的工具绕过。已有执行索引最多64项，明确截断，不带旧参数或正文；成功的记忆读取提供绑定原工具记录的回查引用，其内容仍经过当前来源核查。成功状态不能证明原任务完成；无来源工具结果不因此恢复成当前事实。重复调用编号在执行前拒绝，避免覆盖原有审计记录。已执行操作不撤销 / 重放，尚未执行操作不能假称完成。

仅一次恢复尝试，最多三轮主模型请求，整个恢复共享30秒取消信号。路由内部故障转移、摘要调用另计，计时器不能抢占同步文件扫描；正常请求不增加生成次数。再次变化、预算耗尽、取消、急停或交接不自动复活。最后等锁期间的新插话仍交给当前轮次处理，不因过早移除 running 而丢失。恢复成功按新凭据保存一个最终回答；失败只存说明。旧流式草稿可能已显示，不能收回，过程原记录保留。

为避免把失效草稿 / 旧操作混入学习，发生恢复的整轮暂不送入 PRIME。此恢复只重核答复，不自动继续未完成的写操作；自主醒来 / 子 agent 等路径尚未接此恢复策略。工具执行期间变化、无凭据旧路径、文件 / 项目 / Canvas 等未绑定材料和未收到的远端修订仍有独立边界，不代表全 C07 完成或真实语义 / 前台延迟验收。

## 5. 权威文件与重建

`AdaptiveArchive` 每次操作仍枚举、读取和核对受管结果完整内容及本机发件箱，再调用 `AdaptiveGraph.rebuild` 核对投影。宿主必须在既有灵魂 exclusive 内调用，避免与 Git 合并 / 发布交错。普通查询不得直接调用绕过核对的底层 graph；底层仅供安装、重放和工程测试。

- 已交付文件是权威副本；本机 pending、尚未安装的结果仍由持久发件箱提供。标记为 written / published、或曾安装后 Git 提交失败的结果，文件缺失时不得用发件箱偷偷补成可用认识。发布器本身的恢复规则保持原有职责。
- 每个文件校验 agent、UUID、大小和格式；目录 / 文件链接被拒绝，临时 `.tmp` 不读取，其他未知文件报错。未知 payload 不进入语义图；同一个已知语义结果变成另一 payload 不能绕过一致性检查。
- 重放要求从第 0 代连续到当前代；记录版本、历史引用和输入 hash 覆盖仍须成立。原文可能已经修改或尚未复制，因此重放不要求旧原文仍可读取；实际查询时依然逐条校验当前来源。跨身体本机来源 revision 不必相等，agent / ID / hash 必须匹配。
- 已见结果的 ID / 摘要保留在 batches；缺失、修改、同代分叉或中段缺口均使重建失败。事务失败保留旧投影供审计，archive 入口抛错，不把旧投影返回为当前认识；文件恢复完整后，下次调用自动恢复。
- 备份可保存 `checkpoint()` 的 `{generation,artifact,digest}`，新数据库恢复时作为 minimum 传入。没有本机见证、也没有备份检查点时，仅凭一组连续文件无法证明尾部未丢失；本库不声称能检测这种信息缺失。M4 完整备份必须纳入检查点、原始来源及未交付结果，不能只复制部分 Markdown。

当前单次枚举 / 发件箱核对至多 10000 项，语义结果总量至多 64 MiB；逐项读入并检查上限，超限报错，不返回被截断的部分图。完整重放成功后，按 SQLite 连接和 agent 在内存保存权威链摘要与实际投影摘要。只有权威内容和投影逐行摘要均一致时才跳过重放；不依赖 mtime、文件大小或 generation 单值。文件 / 投影变化、连接重开或外层事务回滚导致摘要不符时重新验证完整链，来源可见性与依据状态每次重算。首次或变化后的重放在批次间复用已验证的当前记录映射，避免每个批次再次解析全部旧记录。

摘要见证为 WeakMap 内存项，不改变持久格式；核对实际投影超过128 MiB或1010001行时不使用此优化，仍走原有重放，不以缓存预算收紧格式范围。100 / 500 / 1000条独立合成认识的基准及实际宿主100次查询见[阶段记录 §4.25](ADAPTIVE_MEMORY_PROGRESS.md#425-m2-权威核对下的投影复用与读取规模测试2026-10-27)。500毫秒截止仍不能抢占同步扫描；长依赖链、更大修订历史、跨身体规模负载和完整首字延迟仍未验收。这是受控原型的恢复入口，不是已验收的海量图存储。

## 6. 后台接线与剩余门禁

提案按实际路由准备格式：Google 使用 [generationConfig 的 JSON MIME 与 responseSchema](https://ai.google.dev/api/generate-content#generationconfig)，schema 只在协议字段发送；其他协议保留原有完整提示。两种形式均预算完整 schema，供应商拒绝原生约束时按既有路由故障转移，不原地降级后伪称原生成功。宿主仍拒绝 Markdown 围栏、截断、工具调用和非法引用 / 版本；结构化输出不能验证语义。普通聊天不使用此约束。开发观察保留实际请求 schema 和固定失败原因，不能把90秒无数据超时当成 JSON 失败或语义不合格。


宿主现通过默认关闭的 adaptiveMemory.semantic 开关运行增量整合 / 重评，复用控制台供应商路由、写锁、持久任务和自动发布。存档入口已接入后台锁与生命周期，失败状态可通过既有 status 查看。现有 API Key 路由用于后台，ADC 仍只用于开发；不复制 ADC 或保存短期令牌。集中主机本机的前台认识查询现已接入；试验开启时 M1 原文观察路径仍停止注入。远端读取虽已接入，全局纠正覆盖仍未完成，不代表旧检索路径已全部满足 C07。

`adaptive-worker.ts` 当前最多扫描 1000 条记录 / 100000 个来源与引用项，最多带入 100 个来源 / 256 KiB 提示；超限保留失败任务，不截断后声称处理成功。编辑后的消息通过现有来源修订触发新整合，不再因任一旧引文失效而阻断全图。提示中 `sourceChanges` 标识原文已不可用的旧记录及可读取的新来源句柄；它们只是待核对的历史认识，不作为新证明。模型引用旧文字、旧 hash 或递归失效记录仍被既有安装器拒绝。空提案只完成本次检查，不改变认识依据状态；失效记录还可由稳定重评任务检查一次，不无限空转。

来源被忽略、删除或改成助手角色时，增量输入排除其直接派生记录和按 ID 追溯的全部显式下游，包括旧版本依赖，避免仅隐藏引文却泄露派生正文；这是保守的模型输入过滤，不修改存档，也不直接撤回仍有独立依据的认识。新来源集合只包括当前任务、当前 hash 已被认识引用的资料和修订匹配的已处理回执；其他消息尚未处理的编辑不会提前进入检查点。未来的大历史 / 权限读取仍须独立验收。

后台单飞，普通整合优先，连续本机忙碌最多等待 30 秒后尝试；每次生成有 150 秒时间墙。重评预算以最新整合回执为轮次保存在本机 KV：每五次调用启动 60 秒冷却，到期无需新输入自动续做；每个目标同轮至多五次，至多登记 1000 个不同目标，避免靠不断换任务键 / 新造对象无限调用。调用前预扣，失败 / 崩溃不退款；新整合回执开始新轮次。旧的整轮五次 KV 预算一次升级为 version 2；未知版本或损坏的新预算显式失败，不重置额度。状态分别显示 review-cooldown 和 review-limit。窗口校验使用既有保守 UTF-8 字节估计，不是真实 tokenizer。

尚须完成跨语境真实语义门禁、真实语义留出集、大历史选择、前台纠正覆盖、跨身体资源优先级与性能门禁。失效来源重整合已有工程闭环，真实语义成功率尚未验收。完整备份、远端同步和检查点保存仍须 M4 验收；开源组件完整选择和集成也未结束。

没有新增守护进程或运行依赖。配置与既有管理 RPC 增加 semantic 字段；main 引入相关库后，构建脚本将完整 Graphiti 许可 / 修改说明嵌入跨平台分发的 main.cjs。当前只做受控后台试验，默认不启用，不能据构建或合成 HTTP 测试宣称 M2 通过。

统一供应商结果及后台 lastModel 现保留 input / output 和可选 reasoning / total。Google 按 promptTokenCount + toolUsePromptTokenCount 计输入，candidatesTokenCount + thoughtsTokenCount 计输出；reasoning 是后者的子集，total 原样保存供应商总量，缺失或非法字段不覆盖先前累计快照。该映射依据 [Google UsageMetadata](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/rest/v1/GenerateContentResponse#UsageMetadata)。思考正文不进入回答或记忆提案。每日 SQLite / 身体同步仍只存聚合 input / output / cost，无新 schema；最后模型明细存在既有本机 KV，不是逐调用账本。费用为配置单价估算，未处理缓存折扣、分层价格或未知失败用量，旧记录也不追溯补算；ADC 开发报告仍与生产状态分开。


### 派生检索索引的候选边界

`semanticCandidates` 与现有词面查询共用证据 / 来源计算，返回当前候选正文、可见对象名和完整认识的摘要 key。认识修订、时间、根来源、共同支持分支或可见对象发生变化时摘要变化；候选中不包含不可访问来源、失效支持、隐藏反证导致失效的结论或未解歧对象的隐藏名称。

`selectSemantic` 可接受内部近邻次序 `{queryHash, keys}`。它只把匹配本次问题且仍在当前候选中的摘要参与 Graphiti RRF 融合；先核对再截取，重复摘要不加票，过期 / 隐藏摘要不能恢复认识，形状错误或超过1000项退回同门禁词面路径。每路至多6项、最终至多6项，输出仍是当前完整认识；不把排名当身份、事实或相关性真值。

宿主现可在锁外取得真实 E5 近邻，再在当前快照执行上述核查。adaptive-vector 的独立 worker 保存按 agent / 模型空间 / 候选 key 隔离的 SQLite 派生向量，不写灵魂。文档128 token分块、32字符重叠，查询480 token分块、64字符重叠，最多128块；每块重新分词核查，不默默截去尾部。查询至多等待100ms，超时 / 组件未就绪退回词面，整次读取500ms截止不变。背景任务逐块让查询优先，单个候选全部块完成后才提交；过期快照不能提交在途结果。重启核验缓存摘要 / 形状，损坏行重建，当前快照未包含的旧 key 删除。中心自动准备固定组件、失败退避并在停止时取消准备 / 释放推理。确定损坏的派生库会隔离再重建，暂时索引失败按2至60秒重试；分块超限 blocked，不重复计算。上述工程恢复已有实际验证，完整多身体、大历史与正式语义仍待验收。没有新查询 RPC 或用相似度替代证据的规则。
