# 自适应记忆：认识版本与证据依赖

状态：M2 阶段内的存储 / 计算库与受控后台试验，已有合成工程测试及独立真实模型开发调用；默认关闭的宿主后台已接线，前台语义查询未完成。不是 M2 放行记录。目标见[行为契约](ADAPTIVE_MEMORY_CONTRACT.md)，结果传输与发布见[存储协议](ADAPTIVE_MEMORY_STORAGE.md)，实际测试见[阶段记录](ADAPTIVE_MEMORY_PROGRESS.md)。

## 1. 为什么把这些规则留在宿主

模型负责提出“这句话可能指谁”“哪些证据共同支持这条认识”“新话纠正了什么”。宿主负责身份、版本、精确出处、事务、依赖计算和访问过滤。格式正确不能证明模型读懂了原文，也不能证明推论逻辑有效；后者必须通过真实语义评测。

实现入口为 `runtime/src/memory/adaptive-evidence.ts`、`adaptive-graph.ts` 与权威存档入口 `adaptive-archive.ts`。提案层已改编固定版 Graphiti 的抽取 / 时间提示规则，保留许可证与修改说明；[组件实验](ADAPTIVE_MEMORY_COMPONENTS.md)仍不等于完整上游服务集成。

## 2. 最小记录

信封 `payload.schema` 为 `quetzal-adaptive-semantic-v1`，`data` 为 `{baseGeneration, records}`。一个批次 1～100 条记录；每条记录共有宿主 UUID v4、连续递增 `revision`、`present / withdrawn`、`realm` 和审计出处 `reasons`。拒绝未知字段，不接受模型自行写入 `active` 或 `verified`。

| 记录 | 主要字段 | 含义 |
|---|---|---|
| node | name、labels | 同名可有多个对象；标签开放，不预设职业、家庭或创作主题树 |
| mention | anchor、candidates、unknown、resolved | 具体的一次提及；候选引用对象的具体版本，允许未知、多个候选和未解歧 |
| claim | text、nature、participants、occurred、valid、supports、counters | 有来源的陈述 / 推论 / 假设；参与者经 mention 引用，支持与反证分别成组 |

`realm={world,context}`：world 为 real / fiction / hypothetical / unknown；context 是宿主维护的语境标识，不用模型随意拼写的标签当世界身份。具体语境识别与标识分配尚待接线。不同语境的对象不能直接互相代入；跨语境比较应另行明确表达，不能靠复用同名节点暗中连接。

出处为 `{kind:'source',source,hash,start,end,quote}`，位置按 JavaScript UTF-16 偏移，必须与当前来源 hash、原文切片完全一致，边界不得劈开代理对。模型端未来可提供原文引用，但最终位置应由宿主对齐；重复引文不能任意挑选。目前已有 `adaptive-proposal.ts` 规范化器，严格检查重复引文定位、宿主 ID / 版本和当前句柄，见[评测与提案接口](ADAPTIVE_MEMORY_EVAL.md)。

记录引用为 `{kind,id,revision}`，不能只指向“最新”。一句话可以有多个 mention，也可以为多条 claim、多组依据提供材料；本批不把一句话限制到一个主题。对象名称、标签和文字内容本身都不是充分证据。

`occurred` 与 `valid` 均保存 `{text,earliest,latest}`：保留原文时间描述，无法确定时边界为 null。确定边界使用 UTC ISO 时间；日期倒置、非法日期和无原文描述却填时间被拒绝。消息时间保持在原始消息里，处理时间在结果信封里，均不覆盖事件时间。时间语义解析和时区判断仍属于待评测的模型 / 宿主协作，不由格式校验保证。

## 3. 支持、反证与循环

支持和反证都用 `{id,premises,assumptions}` 组成依据组。组内前提是 AND，不同支持组是 OR；前提可为精确原文或具体 mention / claim 版本。node 不能直接充当推论依据。`reasons` 是版本变动的审计来源，不被暗中追加为 claim 的必要前提，否则会把独立依据的 OR 错变成全局 AND。

一个无附加假设的反证组全部成立时，阻断该 claim 和依赖它的下游。反证也绑定版本：反证本身被撤回或纠正后，旧版本引用不能继续有效。有附加假设的反证留作候选，不作为确定阻断。

计算先求正向最小闭包，再交替收紧反证假设下的上下界；不按记录排列次序裁决相互反驳。没有独立根的正向循环不能自证；有根时传播依据，根集合按来源 ID 与 hash 去重，同一发言重复加工不会变成多份独立证据。来源角色只有 user / ambient 可作为当前库的独立根，agent 自己的重复陈述不增信；外部工具证据如何准入仍待实现，不偷换成用户确认。

| 状态 | 当前含义 |
|---|---|
| supported | 有当前有效的支持组和参与者绑定，且没有未决 / 成立的反证阻断 |
| ambiguous | 该次提及保留歧义，未解决指向 |
| conditional | 必要前提当前可用，但仍有显式附加假设 |
| contested | 已有成立的反证组 |
| indeterminate | 反证循环等导致上下界未能确定 |
| unsupported | 缺少当前完整依据，包括失效的旧版本引用 |
| withdrawn | 当前版本已撤回 |

这些是依据状态，不是真值概率或个人确认状态。`supported` 不把 inferred / hypothesis 改成 reported，更不升级旧记忆系统的 active / verified。自然语言里的条件蕴含是否成立、反证是否真的反驳，依然需要语义评测；本库不是通用定理证明器。

## 4. 纠正、事务和读取

纠正保留同一记录 ID，新增版本。被修改的 mention / claim 使旧版本依赖立即失效；不会将所有历史昵称全局替换。某个 claim 的一个支持组失效时，其他独立充分组仍可使用，无关 claim 不连带撤回。下游重推需要新批次，不能只把引用版本改成最新而保留原结论。

`dependentRecords` 在纠正前的快照上，以被替代的具体版本为起点计算传递影响，覆盖对象候选、参与者、支持与反证引用；循环去重，默认 100000 步上限，超限抛错，不交付不完整清单。已撤回记录不作为待修复节点。返回的是需要检查的下游，不是撤回命令：有其他独立依据的认识仍可 supported。开发提案输入提供当前精确版本的直接下游句柄，要求模型重新核对原文与纠正；开发报告保留未被本批修订的受影响候选。

`adaptive-review.ts` 现提供内部重评执行入口：从存档发现 present 记录的旧版本 / 已撤回依赖，以及精确来源已经变化的记录。取当前依赖闭包，并补入同语境、有可读来源的已有对象及定义，避免旧闭包只含错误绑定而迫使模型新造对象；名称相同仍不能自动合并。以目标、闭包 / 候选版本和来源 hash 生成稳定任务键，通过现有 `AdaptiveStore.scheduleSource` 定向入队。纠正提交与任务发现之间即使崩溃，下次扫描仍能重建工作；任务的租约、退避、五次尝试上限和取消沿用 M1。只有无关整图代次改变不生成重复任务，候选或来源真的变化可以触发新检查。每次只重评一个目标，允许新增必要记录，不允许借重评修改其他既有认识。扫描沿真实记录引用优先上游，补充的候选对象不会凭空产生调度依赖；上游退避或额度不足时延后其下游，独立分支仍可推进。引用环内不存在拓扑序，按稳定 ID 遍历打破排序环，仍受版本门禁、证据计算和目标额度约束，不能凭顺序恢复证明。

调用前后使用宿主提供的灵魂 exclusive，模型等待期间释放锁。新认识批次仍经过 archive.accept；空提案也经 archive.complete，在同一任务完成事务内核对整图 generation 和全部输入修订 / hash。空提案只代表本次无合理修改，不使 unsupported 变成 supported；依赖后来发生变化可产生新的任务。用户取消、急停、关闭、超时和迟到响应均不得安装。下一层因上游修订出现旧引用时会被后续扫描发现，不机械批量换版本。

当前原型扫描上限为 1000 条当前记录，每个依赖闭包连同对象候选至多 100 条记录 / 100 个来源、256 KiB 提示；目标所需来源缺失 / 忽略 / 改为助手发言，或超过上限时显式 deferred，不能伪造完成。来源可读但 hash 变化时可以重评，旧引文标为 unavailable，模型必须重新提供当前原文的精确引用才可修订；不能把旧 hash 换成新 hash 后沿用旧结论。它还不覆盖没有显式依赖的新关联发现。开发执行器至多连续运行五步；生产后台采用分批冷却自动续做，已有工程回归，但真实长链语义质量、大历史候选选择及状态界面仍待完成。因此不是完整生产纠正闭环。

原文读取覆盖层 `adaptive-reading.ts` 现在根据全部已知版本计算每条来源的修订提示：旧依据按精确历史 revision 追踪，保留旧 hash / UTF-16 片段位置；当前来源已编辑时不能把旧偏移套到新正文。提示针对某条认识，不删除原文，也不撤回同段的独立认识。只有可见与全局依据均支持时附上当前内容 / 性质 / 语境及可见根来源 ID / hash；隐藏纠正或反证不会因可见子图单独成立而恢复旧结论，也不返回隐藏正文。

实际 `context_read` 经 `contextReadChecked` 在灵魂 exclusive 和同一 SQLite 快照中读取当前原文与修订；每页都带提示，offset / limit 只定位原文，不能翻页绕过状态。`recall` 的命中和前后邻句同样核对，忽略来源会被过滤，候选在等锁期间改变则要求重新检索。没有可解析消息来源的旧缓存 / 文档仅提示无法逐项核对，不据此宣称其内容已完成语义纠正。

读取只承诺本机已收到的快照，不声称中心最新。后台未启动或新功能关闭后，只要本机仍有认识存档目录 / 投影见证，这两个工具仍执行修订核对；只有没有任何此类状态且功能未启用时才保留旧输出路径。归档损坏或来源不可访问不能退回旧缓存正文。修订阶段含等锁的截止为 500 毫秒，超时后排队回调不再执行；同步扫描另在返回前核对耗时，**不能据此声称同步扫描不会阻塞事件循环**，真实负载性能仍待测。至多 1000 个请求来源、1000 个当前对象、10000 个版本、100000 步追溯，修订结果 256 KiB、格式化召回 512 KiB 上限，超限拒绝完整结果。

默认历史视图也核对当前原文与修订，不改调用者轨迹；来源编辑后重建带角色 / 时间的资料，忽略或删除后只留占位，旧图像不沿用。自动摘要在本机计划保存来源 ID 和核查摘要值；只有全部被压缩条目绑定消息来源时才写凭据。无凭据 / 版本变化就不继承，历史与旧摘要来源并集超过1000条时放弃旧摘要，不无限增长依赖。窗口准备前后核对，变化清除摘要缓存并最多重建一次，连续变化拒绝本次请求。手动 session_compact 摘要没有来源版本，只作存档，不再截断最多1000条可用原文。全局 generation 变化也会保守使摘要失效，尚未优化为局部增量。

旧结构化候选由 `adaptive-material.ts` 在主模型准备前后与历史同快照核对：只识别 evidence.ref 中精确 message:<id>，不扫描正文猜来源；重读当前受管文件 / legacy 文件，文件已变则拒绝旧候选。命中旧选择缓存仍重新核对。可访问材料附相关局部修订，不用当前消息存在证明旧断言仍成立；任一消息出处不可访问时，因旧格式无逐句来源映射，不输出整条派生正文及证据引语，保留管理元数据。原 state / validation 不改写，读取另有 historical / unverifiable / unavailable 状态。

实际 memory_records 同样核查。note_read 识别受管结构化记录并检查会话范围、实际文件别名；认识批次核对权威文件和全部输入后才输出带修订的历史存档，任一输入不可访问则隐藏 payload。普通无出处 Markdown 不猜引用，仍返回带未核实说明的原文；普通笔记中的格式示例不会仅因出现格式标记就成为受管记录。受管格式损坏不能退回普通正文。单笔记读取256 KiB、格式化结果 / 旧记录列表512 KiB上限。

recall 文档命中复用 prepareNoteReading / 快照 render，先按当前会话范围和来源可访问性过滤，再取请求数量；笔记受管内容不使用索引旧片段，而是输出完整读取视图。普通笔记片段必须对应当前完整正文，日记 / 常驻条目也按来源和正文 / 标题核对；变动时要求重新检索，不返回混合版本。候选最多200项，来源 / 图 / 截止 / 输出上限保留，不能据此声称海量历史全召回。

旧语义选择模型在有界候选正文之外接收完整 reading 字段，不发送不可访问正文，也不接受模型猜回未发送的key。缓存保存全部参与选择候选的来源核查摘要值；同状态复用，来源hash或认识变化重选。模型等待期间变化时丢弃该选择结果，不入缓存；词面降级和关闭旧语义选择器时仍核查来源访问。主模型发送前的核查继续保留。

系统提示的跨会话近况现由 systemMessage 保留对象绑定，每次准备捕获至多五会话各四条消息，取原文与修订的同一快照；等锁期间候选改变则拒绝，摘要期间变化最多重建一次。原文节选最多160字符，修订头完整，4000字符局部预算按整项保留或略过，并提示 recall；不截断修订后保留旧正文。来源忽略 / 删除不展示，旧手动摘要只提示回查。实时输入与草稿尚未绑定持久来源，只呈现运行状态。quick 内省经模型准备钩子对每个候选 / 故障转移重新核查。系统资料参与本轮准备摘要值，但不混入仅由本会话历史生成的持久摘要凭据。

这仍未覆盖任意无出处的系统派生资料（目标、Canvas 等）及远端语义查询；本轮未绑定消息来源的工具轨迹也不能据此认定完成纠正。semantic=true 时新增 adaptive 查询仍 unavailable；关闭功能后其他旧路径的全局一致性也仍待补齐。不得把本段标为 C07 全项通过，或把非中心配置的单进程工具测试当成实际多身体同步验收。

SQLite 可选投影保存 meta（格式版本 2、整体 generation）、batches（结果 ID / 摘要 / 代次）和 records（记录 ID / revision / 文档 / 结果 ID）。初始化失败整体回滚；未知版本或损坏元数据拒读。投影 schema 1 原子迁移到 2，记录的外键从本机发件箱改为结果批次表，使另一具身体无需伪造本机任务 / 发件箱即可重建。该版本独立于 M1 队列 schema 2，也不改变灵魂规范 v14。

`AdaptiveGraph.accept` 在已有任务接受事务内校验全部来源与递归依赖输入。批次 baseGeneration 必须等于当前 generation，每条版本必须连续，当前引用须同语境且存在；允许撤回记录保留实际存在的历史引用用于审计。发件箱、记录、代次、处理回执和任务完成同时提交，安装返回 false 或抛异常都整体回滚。整体代次 CAS 较保守，可能拒绝本来互不冲突的并发批次；先保正确，后续按冲突率决定是否细化。

读取使用 SQLite savepoint 快照，一次计算缓存来源，避免跨连接更新造成同轮混合版本。默认工作上限 100000 个计算步骤；超限抛错，不能把半算结果当成有效证据。当前全图读取尚未做大历史性能验收，不应直接放入前台请求。

可见结果同时满足全局依据和调用者可访问依据：隐藏的已知反证不能因为权限过滤而让错误结论复活。有其他可访问的独立支持组时可以保留结论，但只返回有效支持组，不泄露隐藏来源的反证 / 审计正文。现有读取器是内部接口，生产权限上下文仍须接线，不能让调用方任意指定来源读取函数。

## 5. 权威文件与重建

`AdaptiveArchive` 每次操作先枚举受管结果文件、核对本机发件箱，再调用 `AdaptiveGraph.rebuild` 原子重放。宿主必须在既有灵魂 exclusive 内调用，避免与 Git 合并 / 发布交错。普通查询不得直接调用绕过核对的底层 graph；底层仅供安装、重放和工程测试。

- 已交付文件是权威副本；本机 pending、尚未安装的结果仍由持久发件箱提供。标记为 written / published、或曾安装后 Git 提交失败的结果，文件缺失时不得用发件箱偷偷补成可用认识。发布器本身的恢复规则保持原有职责。
- 每个文件校验 agent、UUID、大小和格式；目录 / 文件链接被拒绝，临时 `.tmp` 不读取，其他未知文件报错。未知 payload 不进入语义图；同一个已知语义结果变成另一 payload 不能绕过一致性检查。
- 重放要求从第 0 代连续到当前代；记录版本、历史引用和输入 hash 覆盖仍须成立。原文可能已经修改或尚未复制，因此重放不要求旧原文仍可读取；实际查询时依然逐条校验当前来源。跨身体本机来源 revision 不必相等，agent / ID / hash 必须匹配。
- 已见结果的 ID / 摘要保留在 batches；缺失、修改、同代分叉或中段缺口均使重建失败。事务失败保留旧投影供审计，archive 入口抛错，不把旧投影返回为当前认识；文件恢复完整后，下次调用自动恢复。
- 备份可保存 `checkpoint()` 的 `{generation,artifact,digest}`，新数据库恢复时作为 minimum 传入。没有本机见证、也没有备份检查点时，仅凭一组连续文件无法证明尾部未丢失；本库不声称能检测这种信息缺失。M4 完整备份必须纳入检查点、原始来源及未交付结果，不能只复制部分 Markdown。

当前单次枚举 / 发件箱核对至多 10000 项，语义结果总量至多 64 MiB；逐项读入并检查上限，超限报错，不返回被截断的部分图。目前每次重放全链，尚未做增量缓存与大历史性能验证，不应直接接到前台关键路径。这是受控原型的恢复入口，不是已验收的海量图存储。

## 6. 后台接线与剩余门禁

宿主现通过默认关闭的 adaptiveMemory.semantic 开关运行增量整合 / 重评，复用控制台供应商路由、写锁、持久任务和自动发布。存档入口已接入后台锁与生命周期，失败状态可通过既有 status 查看。现有 API Key 路由用于后台，ADC 仍只用于开发；不复制 ADC 或保存短期令牌。前台语义查询与纠正覆盖层未完成：试验开启时新增 adaptive 原文观察路径停止注入，不代表旧检索路径已全部满足 C07。

`adaptive-worker.ts` 当前最多扫描 1000 条记录 / 100000 个来源与引用项，最多带入 100 个来源 / 256 KiB 提示；超限保留失败任务，不截断后声称处理成功。编辑后的消息通过现有来源修订触发新整合，不再因任一旧引文失效而阻断全图。提示中 `sourceChanges` 标识原文已不可用的旧记录及可读取的新来源句柄；它们只是待核对的历史认识，不作为新证明。模型引用旧文字、旧 hash 或递归失效记录仍被既有安装器拒绝。空提案只完成本次检查，不改变认识依据状态；失效记录还可由稳定重评任务检查一次，不无限空转。

来源被忽略、删除或改成助手角色时，增量输入排除其直接派生记录和按 ID 追溯的全部显式下游，包括旧版本依赖，避免仅隐藏引文却泄露派生正文；这是保守的模型输入过滤，不修改存档，也不直接撤回仍有独立依据的认识。新来源集合只包括当前任务、当前 hash 已被认识引用的资料和修订匹配的已处理回执；其他消息尚未处理的编辑不会提前进入检查点。未来的大历史 / 权限读取仍须独立验收。

后台单飞，普通整合优先，连续本机忙碌最多等待 30 秒后尝试；每次生成有 150 秒时间墙。重评预算以最新整合回执为轮次保存在本机 KV：每五次调用启动 60 秒冷却，到期无需新输入自动续做；每个目标同轮至多五次，至多登记 1000 个不同目标，避免靠不断换任务键 / 新造对象无限调用。调用前预扣，失败 / 崩溃不退款；新整合回执开始新轮次。旧的整轮五次 KV 预算一次升级为 version 2；未知版本或损坏的新预算显式失败，不重置额度。状态分别显示 review-cooldown 和 review-limit。窗口校验使用既有保守 UTF-8 字节估计，不是真实 tokenizer。

尚须完成跨语境关系、真实语义留出集、大历史选择、前台纠正覆盖、跨身体资源优先级与性能门禁。失效来源重整合已有工程闭环，真实语义成功率尚未验收。完整备份、远端同步和检查点保存仍须 M4 验收；开源组件完整选择和集成也未结束。

没有新增守护进程或运行依赖。配置与既有管理 RPC 增加 semantic 字段；main 引入相关库后，构建脚本将完整 Graphiti 许可 / 修改说明嵌入跨平台分发的 main.cjs。当前只做受控后台试验，默认不启用，不能据构建或合成 HTTP 测试宣称 M2 通过。

统一供应商结果及后台 lastModel 现保留 input / output 和可选 reasoning / total。Google 按 promptTokenCount + toolUsePromptTokenCount 计输入，candidatesTokenCount + thoughtsTokenCount 计输出；reasoning 是后者的子集，total 原样保存供应商总量，缺失或非法字段不覆盖先前累计快照。该映射依据 [Google UsageMetadata](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/rest/v1/GenerateContentResponse#UsageMetadata)。思考正文不进入回答或记忆提案。每日 SQLite / 身体同步仍只存聚合 input / output / cost，无新 schema；最后模型明细存在既有本机 KV，不是逐调用账本。费用为配置单价估算，未处理缓存折扣、分层价格或未知失败用量，旧记录也不追溯补算；ADC 开发报告仍与生产状态分开。
