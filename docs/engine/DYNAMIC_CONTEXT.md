# 动态上下文预算与工作状态

本页描述 `engine/src/context-manager.ts` 的真实实现。生产装配位置与当前验证结果由宿主开发记录同步维护；独立模块通过 ports 接入，不 import runtime、数据库或模型凭据。

## 请求前重建有限窗口视图

每次模型调用前，`runTurn` 在建立本轮模型取消信号后调用可选 `EnginePorts.prepareContext(request)`。原始 `messages` 仍持续追加，prepare 生成克隆视图，不删除原数组或唯一行动证据。`ChatRequest.prepareForModel({contextWindow,maxOutputTokens,model})` 供路由针对具体候选模型和故障转移窗口再次准备；应从完整原消息重算，不能从上一个已裁剪视图继续丢内容。

`ContextManager.prepare()` 输入完整消息、工具 Schema、窗口、输出预留、可选工作状态/检索记忆、signal 和 protectedFrom。返回 `ContextPlan`，包含实际视图、稳定消息编号、保留/压缩来源编号、分项估计、摘要信息、工具结果投影与未纳入的记忆编号。`source(id)` 返回本轮保留的完整原消息克隆，供宿主实现回查；编号不是持久化数据库主键。

## 估计与明确溢出

文本使用 UTF-8 字节数加每条消息/工具 framing 开销，工具 Schema 全部计算，输出单独预留，另加窗口 5%（至少 128）的安全余量。图片默认按至少 4096 和编码字节量的启发式余量估计，允许注入模型已知的图片估计。`estimate.inputTokens` 已包含图片，`imageTokens` 只是其中分项，不能再相加。

这是保守估计方案，不是真实 tokenizer，也不能证明不同供应商的实际输入一定在窗口内。宿主应依据模型窗口、实际用量和上下文错误持续校准；不能把字符数或公开 context 元数据当作已精确计数。输出预留和候选窗口由宿主路由提供。

所有原始 system 消息、工作状态、protectedFrom 起全部 user 输入、最新消息组和未完成工具响应组固定保留。未指定 protectedFrom 时保守保留全部 user；宿主可传本轮首个用户输入索引，让先前会话内容参与摘要。本轮插话和用户约束不能因为更新 recency 而被丢弃。固定内容、工具 Schema 或极大用户输入放不下时抛出 `ContextOverflow`，不截系统政策或请求来伪装成功。

## 工具协议与完整证据

assistant 的同响应工具调用与紧随的对应 tool 结果组成不可拆组。未返回全部结果时整组固定，不能只保留已完成 call。孤立结果、重复或不匹配编号明确报错。

很长的工具结果只有存在宿主提供的真实回查引用时才生成头尾节选投影；保留 role/name/toolCallId/error 与组配对，并注明节选不是全文。完整结果仍在原消息和 source(id)，实际存储/读取工具由宿主管理。没有引用时不削掉唯一证据，必要时明确溢出。

## 摘要与有限失败回退

摘要放在稳定 `context:summary` slot，独立于最近 N 条历史查询。较早可压缩消息按完整消息组分块，注入的摘要服务接收 entries、previousSummary、maxTokens 和同轮 signal。默认每次最多 4 块，单块输入预算 8192、摘要正文预算最多 1024；参数必须为正整数。缓存最多 32 条，按完整内容、来源和预算匹配，避免同内容反复调用。摘要正文超预算或为空视为失败，不硬截模型摘要。

摘要失败、输入过大或分块次数耗尽时，只有每条被省略内容都有非空引用，才返回明确“未成功摘要、不能推断事实、必须按引用回查”的有限降级内容；引用也必须在窗口内。缺引用或摘要/引用仍放不下则 ContextOverflow，不静默删除旧证据。取消不会变成成功降级，即使注入服务忽略 signal，prepare 也停止等待。

引用 callback 和 source(id) 只提供引擎边界。生产宿主必须把引用连到实际可调用的回查工具/行动记录，不能把不可读取的编号宣称为完整证据检索。独立 ContextManager 不向公开仓库保存人格、用户事实或工具原文。

宿主 `context_read` 的实际工具入口现在经 `contextReadChecked` 核对本机自适应认识存档；有来源指针的每页都附带已知修订状态，正文与修订来自同一数据库快照，分页偏移仍仅计算原文。无来源的旧缓存明确无法逐项核对。关闭后台生成不抹去已存在认识的工具读取门禁。宿主已在默认历史与旧记忆候选的准备前后核对来源，变化时调用 invalidateSummaries 清除派生缓存，持久摘要只有绑定来源版本且未变化时继承；具体边界见[语义读取](ADAPTIVE_MEMORY_SEMANTICS.md)。这不表示任意无出处资料或跨身体一致性已验收。

## 工作状态与检索记忆

`TaskWorkingState` 包含 goal、constraints、openQuestions、evidence（id/claim/source），全部由宿主显式提供和更新；引擎不从最后几个字符猜测目标，也不自行把推测升级为事实。未传 state 时不生成虚假的任务状态。

`MemoryContext` 包含 id、text、可选 priority/reference，每步可更新。引擎仅按优先级选择放得下的完整条目，不截半条、不默认固定全文知识库；遗漏编号在计划中列明。条件检索、事实检查、长期记忆写入与版本管理仍由对应宿主服务负责。

## 独立验证范围

`engine/test/context-manager.test.ts` 验证系统/约束保留、稳定摘要/cache、完整历史来源回查、小窗口候选重新准备、Schema/输出/图片分项、工具组与超长投影、无引用失败/overflow、分块上限、工作状态/记忆预算、取消，以及真实 20 步工具循环：原数组增长、请求视图持续受估计窗口限制。它使用合成模型/工具，不证明真实供应商的 token 计数、摘要正确性或长期任务成功率。

## 系统提示中的跨会话资料

生产 `systemMessage` 保留政策字符串与当前会话绑定；`prepareSystemReading` 捕获其他会话近期消息，交给与历史 / 记忆候选相同的 withAdaptiveSources 快照核对。政策部分仍每轮生成，跨会话持久消息每个候选模型准备时刷新。正文按原160字符节选，修订头不截断；4000字符局部预算只保留完整项目，超限明确提示回查。来源不可访问不输出，实时草稿尚无持久来源时只显示运行状态，未绑定版本的手动摘要也不输出旧正文。

跨会话来源及完整呈现文字参与本轮准备前后比较；摘要等待期间变化清缓存并最多重建一次，持续变化拒绝请求。系统资料不进入只覆盖本会话历史的持久摘要凭据。所有来源合并后仍受1000条单次上限及500毫秒快照阶段截止约束；超限拒绝，不承诺大历史或延迟验收通过。

快速内省通过 withSystemReading 复用相同读取，在每个模型候选与故障转移前重新核查；它没有因此获得 ContextManager 的完整窗口预算 / 摘要能力。字符串 systemPrompt 是同步兼容预览，修订模式不嵌入未核查跨会话原文或旧常驻全文；生产不可把 systemMessage 序列化 / 克隆后丢掉对象绑定。目标、Canvas、项目说明及任意外部工具等没有消息来源的资料仍需各自的来源契约，这项接线不代表全部 C07 已完成。

## 已执行记忆工具的读取视图

宿主为 recall、note_read、memory_records、context_read 捕获 AsyncLocalStorage 隔离的读取凭据：agent / body / conv / 工具名、原结果摘要，以及实际消息 hash 和笔记 / 记录 / 文档 / 回查缓存的摘要；不从输出正文猜来源。凭据透过 EnginePorts.recordTool 进入本机 tool_calls.reading，与原始结果一同保存 / 淘汰，旧库自动增加可空列。没有可核查凭据的旧成功读取只给重新读取提示，不假装已补出依赖。

模型准备时将工具来源与历史、系统资料、候选一起核查，完整执行记录也需与候选一致。来源未变时保留历史正文并附当前修订；任一原文 hash / 文档摘要变化或不可访问时，因为没有逐句映射，不输出旧派生正文。原执行记录及原始轨迹不改，也不重放有副作用的工具。工作状态 evidence 改用核查后视图的说明，避免从旧 tool.content 的前200字把失效正文再带回。

宿主给这些工具视图标记 atomic；ContextManager 不做头尾节选，仍可按完整协议组摘要或在失败时给完整回查引用，固定组放不下则明确溢出。原结果超过12000字符时，当前视图保留完整修订并给 context_read 引用，避免从旧截断片段重建。工具回查每页重复当前修订，转读时继续记录原消息 / 文档 / 完整工具行 / 缓存出处；不承诺资料变动前后分页位置稳定。凭据最多1000个消息、200个文档，矛盾快照或超限不产生可用凭据，读取视图 / 分页结果最多512 KiB，既有快照截止继续适用。

这些工具混入摘要时不签发仅属于普通历史的持久摘要凭据。来源凭据只保证本机所知，不证明语义正确或跨身体最新。

历史消息的 process 是控制台展示副本，参数摘要、结果摘录和中途文字没有独立来源凭据。修订模式下 history 与模型准备阶段均只输出执行索引（工具名、调用编号、状态、耗时及文字步骤占位），不把副本再次作为依据。模型准备为附注建立 messageRef 回查入口；context_read 也投影 process，本机 message-tools 指向的完整工具记录则经过当前来源核查。每页重复过程限制和完整修订；缺记录或其他身体只复制过来的附注不会靠调用编号猜来源。原 SQLite 消息、工具记录、控制台展示与未启用修订的旧路径不变。

持久摘要核查摘要值加入读取政策版本，使升级前可能包含旧过程摘录的摘要失效。等锁期间新增 / 替换完整记忆工具引用时，若没有对应核查结果则报错重读，不能退回原始正文。历史回复本身仍以带来源原文呈现；任意外部工具、当轮模型中途文字、PRIME 学习与目标 / Canvas 等派生资料尚未全部建立来源契约，不据此宣称全部 C07 通过。
