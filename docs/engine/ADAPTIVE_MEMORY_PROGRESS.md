## 3. M1 首批接入：2026-10-27

输入基线：`90bbca4`，工作区干净，在 `feature/adaptive-memory` 实施。本批为可审查的阶段内检查点，不是 M1 完成或 M2 开始。实现提交通过 `git log -- runtime/src/memory/adaptive.ts` 定位。

### 3.1 已接入的范围

- 固定中心随非安全模式 runtime 启动 / 停止，默认关闭；共享 `adaptiveMemory` 配置和认证管理 RPC，正式 mesh 身体可查询，灵魂桥不获新方法权限。中心不随心脏协调者迁移。
- 来源仍为 SQLite messages。`adaptive_meta` 固定 agent 和 schema v1；`adaptive_sources` 保存本机来源修订和删除墓碑；`adaptive_jobs` 以来源 / 修订 / 处理器唯一登记，保存取消、错误、重试与租约；`adaptive_receipts` 保存处理回执。
- INSERT / UPDATE / DELETE 触发器与消息事务一起提交；改变相关字段立即清理旧回执并使旧任务失效。同值更新不制造版本。启动和运行中反连接补扫旧数据，不依赖时间或全局最大消息编号。来源修订是本机版本，不声称为跨身体统一版本。
- `source-v1` 每 500ms 调度，单批登记至多 100 条、处理至多 50 条；租约默认 30s，换领后旧令牌不能提交，最多尝试 5 次，退避有上限。显式取消不自动复活。当前处理仅登记来源，不调用 LLM、不产生 Claim、不改原有 PRIME 写入职责。
- 查询沿用全文索引，校验当前来源 / 回执后返回至多 6 条原文观察；前台用约 500ms 网络截止降级，取消传播、急停和关闭后不返回材料。主模型上下文明确标记历史资料、来源和局部快照；不额外发通知。同步磁盘阻塞及大历史性能仍需另验。
- 所有运行数据保存在仓库外 QUETZAL_HOME；灵魂格式仍为 v14，尚未写新长期认识。没有新增依赖、环境变量或独立服务；既有 package scripts 自动纳入新测试并打包新入口，核对后无需改锁文件或部署脚本。
