### 3.4 M1 离线来源修订修复：2026-10-27

输入基线：`4f8c9ba`，工作区干净。此逻辑变更修复 §3.3 第 1 项；其余 M1 门禁仍未通过，M2 不放行。

- 在既有 SQLite 增加 `message_modes`，记录 `{id, mode, revision, writer}`。本机状态修改与版本同事务提交，提交后才发复制事件。逻辑计数器不依赖设备时间；清空 mode 也保留记录。因果后续版本优先，同版本并发 ignored 优先，再按 writer / mode 确定性合并。
- 旧库已有标记迁移为 revision=0、writer 为空的快照，不伪造修改者；无版本旧协议不能覆盖已知版本 / 快照。标记先于原文到达时保留，原文到达后在同一事务采用它。完整恢复语义要求参与的身体升级；不能用无版本旧事件推断真实历史顺序。
- 新增正式成员 mesh 方法 `replica.modes({after})`，每页至多 500 条，每次重连从头比较可变状态，独立于新增消息高水位；最多 400 页，达到上限明确记录为局部快照。旧身体没有方法时仍保留既有消息复制，不把兼容当作修订恢复成功。超过 20 万条标记的持续补做尚需完善与负载验证，不能宣称无限历史已经验收。
- 查询返回前检查本机消息状态和完整来源 hash：即使中心返回 ready，本机已知 ignored 或不同快照的来源也不能进入上下文。此防护与中心修订补齐分别测试，不能互相替代。
- 真实双进程用网关聊天产生来源、强杀中心、卫星离线忽略、中心重启，直接核对中心数据库及两端查询；再强杀中心、离线清空标记、重启，核对材料恢复。原 todo 已移除，6 项集成统计全部通过，0 跳过 / todo。30 次小数据暖查询 P95 为 4.3ms，边界同 §3.2。
