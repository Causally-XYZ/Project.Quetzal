## 1. 目标与已确认的取舍

让同一个 agent 在真实对话中持续积累跨会话理解，自发发现有依据的新联系，进行有界多步推理，并在对象、事实、时间或解释被纠正后调整后续使用的记忆。过程必须可追溯、可恢复、可部署，无需使用者修改代码或维护数据库。

以下为需求方已确认的决策：

1. 第一阶段即接入 Quetzal，用自动化、真实模型、多样化合成案例与代理生活模拟验证完整入口；M0–M5 全部验收并推送后另行开展长期真人测试。真人试用、反馈和人工测试均不属于本 GOAL 的步骤、门槛或完成条件，不长期维护脱离真实入口的演示系统。
2. 同一 agent 全部可访问对话默认参与关联；跨 agent 仍隔离，来源权限不得因建立关联而扩大。共享访问不等于共享说话者身份。
3. 多台身体参与对话，由一处桌面或服务器集中处理记忆。第一版固定记忆主机，进程自动恢复，暂不自动跨主机迁移整个服务。
4. 后台广泛探索，对话中谨慎呈现；与当前话题相关时可以主动提起 insight，明确标注推测，不为此额外发通知或开启对话。
5. 允许临时使用 Python 服务与独立图数据库，但依赖安装、启动、升级、恢复均由部署流程管理。公共同步服务不承载私人记忆计算。
6. 不设固定模型费用上限，但必须记录成本、限制并发和单任务工作量、支持取消，防止无进展的无限研究；前台响应优先。
7. 多身体验证全部在本机模拟：隔离运行时、数据目录、身份与端口，配合独立浏览器上下文、桌面和移动视口。无需真实远端设备；不得把移动视口声称为原生移动端验证。
8. 严格按 M0 → M1 → M2 → M3 → M4 → M5 推进。每个里程碑检验、测试、记录证据并本地提交后，必须成功 push 一次，才能进入下一个；里程碑中间可以只做本地 commit。失败或必需检查未执行时不得放行，push 未成功时不得进入下一阶段。
9. 先借鉴高质量开源组件拼出可工作的原型，再通过对照与消融做减法；不预设必须重写所有第三方实现。
10. 允许有来源且明确表达的跨语境谈论、创作、引用关系，严格隔离不同语境的对象身份与事实依据；不把故事角色当成现实人物，也不把故事事件作为现实事实的证明。该边界于 2026-10-27 对齐；M2 已新增显式 references、依赖修正与正反例，见[语义格式](ADAPTIVE_MEMORY_SEMANTICS.md)，真实语义门禁尚未全部通过。

11. 2026-10-28 确认：新记忆开启时统一负责对话事实保存与纠正；旧自动学习及模型直接写 USER / MEMORY 不再并行生成事实副本。已有旧资料保留为历史参考，关闭新记忆恢复原方案；人格、普通创作文档与管理者明确编辑旧文档分开处理。
12. 2026-10-28 确认：不要求单次记忆100%准确，优先验证合理质量、长期误差不自我强化和持续修正。95%为需求方给出的质量方向，不是当前实测成绩，也不是每个后台候选的准入概率；不能因每个局部语义反例不断追加阶段阻塞。

13. 2026-10-28 确认：备份恢复保留历史，后续发言采用新的身体身份，经控制台重新接回同一 agent、指定记忆中心。避免同名身体从旧计数重发已存在的消息编号；不要求使用者修改代码或数据库。

14. 2026-10-28 确认：产品仍在开发阶段，恢复按当前数据格式和当前运行时设计，不为旧版本混跑、任意旧备份自动导入或跨格式降级维护长期兼容分支。已有开发 / 测试数据需要转换时，针对实际格式提供一次性离线迁移脚本；普通使用与恢复仍走产品入口，不要求使用者操作源码或 SQL。现有兼容代码不因本决策无关清理，也不再作为新设计的必然约束。

15. 2026-10-28 补充：实验须增加题材和错误机制的多样性，不能反复用同一小说轨迹证明新能力。已用于修复的案例保留为开发 / 回归；新输入与检查点先固定再运行，未见评测材料单独保留，不能仅换名字就声称泛化。
16. 同日补充：以持续使用中的收敛方向与稳定性观察正确性——新信息、用户交互和对既有材料的重新理解能否使认识改善，错误是否被修复且不反复自我放大。该目标不等于每一步单调变好、任何错误必然消失或已证明长期收敛；动态观察与边界见[行为契约 C16](ADAPTIVE_MEMORY_CONTRACT.md#c16-验证诚实性)和[评测登记](ADAPTIVE_MEMORY_EVAL.md#2-开发集与留出集分离)。沿用现有日志，不因讨论添加新评测平台或逐次 LLM 审核层；M0–M5及逐阶段测试 / push 顺序不变。
17. 同日追加：需求方暂无时间真人试用，先由 Gemini3.8 Flash 模拟有丰富生活的用户。新增六个月虚拟生活开发轨迹：先冻结新人物，再由独立世界 agent 推进事件 / 环境，角色只凭可知信息生活并自行决定何时使用产品、披露多少；大量生活不进入记忆。表达层加入正常语音转写错误、typo / 漏字等噪声，保留意图与实际送达文本。角色、世界与产品分视图，不把世界真值、未来剧情或标准答案注入 Quetzal。模拟试用与真人反馈分开；时间压缩验证事件语义和纵向使用，不声称真实半年 TTL / 衰减或提醒已验收。具体运行规则见[评测登记](ADAPTIVE_MEMORY_EVAL.md#六个月虚拟生活开发轨迹)。
18. 随后需求方明确覆盖第17项的使用频率：由事件系统按概率掷骰决定是否记录，整体约30%，不再由角色自行选择不打开产品。当前采用每10个可感知事件条目随机抽3个，种子在生成事件前固定、抽样不看语义或产品答案；末尾不足10条不补抽。角色负责生活行动与自然表达，可合并抽中事件、略去细节，未抽中事件不主动披露。早期自主使用轨迹保留为先导，新规则从同一人物起点另跑完整半年；抽样率、实际表达 / 送达与输入噪声分别报告，不以配额推出用户满意度。

### 2026-10-28：恢复当前记忆，不延续旧身体的执行状态

恢复目标是在新身体接续同一个 agent 的记忆：保留原话、历史身份、认识修订、证据依赖和已接受但未发布的结果；历史消息编号与来源 hash 不重写。新身体重新建立设备身份、密钥、连接与记忆中心配置。旧提醒、未完成行动和续跑记录保留可查，但不能仅因加载备份而自动重放；记忆内部的待发布结果和可重建索引与对外行动分别处理。当前已提供离线 CLI 恢复及首次启动检查，已验证旧备份跨身体追回新纠正，以及备份内待发布结果在同一权威链后续更新中的接续，证据见阶段记录 §6.10 / §6.18；不把这些局部成功写成 M4 已完成。

M4 / M5 的恢复验收限定当前格式：损坏与未知格式明确拒绝，恢复操作不覆盖备份原件；从当前备份恢复后，能继续接收尚存身体的新来源与纠正，旧错误不能借恢复变回当前依据。部署启动失败的恢复仍要验证，但不要求旧运行时理解新数据。遇到实际旧开发数据再编写对应迁移脚本，并核对转换前后的来源、修订和依赖；不先建设通用迁移框架或旧版兼容矩阵。

### 2026-10-28：允许误差，检验可修复性与持续使用

M3 继续验证完整关联、多步推理和后台自发探索，不因一次研究未被采用就改成只按需检索。用已有案例观察重复使用、自然语言纠正及跨身体再次使用：既看最终回答，也看错误认识是否被修订、是否被当成独立证据继续强化。允许记录局部语义偏差与稍后修复的遗漏；确定性来源 / 权限 / 已知版本门禁失灵、明确纠正持续无法改变后续使用、系统将自身推测反复当成新增证据，仍须处理。单次新错误与系统性修正失败分开判断，不以“允许5%”掩盖未测缺陷。

原 M2 已放行记录保留；其逐例零错误措辞不扩展为后续阶段必须消灭所有语义偏差。M5 保留150序列及独立质量验证，但旧评分器中的语义零失败条件不是新容错目标的最终定义；进入该阶段时先按最新契约登记统计单位、效用、重复错误暴露和可接受阈值，再查看新留出结果，不修改旧成绩。工程不变量仍须通过。小型修正案例通过仅说明机制在该过程能工作，不证明长期稳定或95%准确率。

### 2026-10-27：先验证完整价值，再补齐细节

用户要求优先证明整体思路可行，停止过度扩充实现和验证设施。经产品、架构、工程三个独立视角各四轮 Gemini 讨论，下一步改为利用现有入口观察完整使用过程：远期碎片帮助当前问题、自然关联、歧义保留、后续纠正改变使用方式，同时不牵强联想。先检查已有轨迹，缺少证据才补最小实验；仅修复阻断该过程的具体问题。

现有图结构、模型补丁格式与验证内核都是实现假说，不因已有投入而必须保留，也不预设应当推倒。区分语言理解错误、结构化表达损耗、材料未取回和前台消费错误；答对还需检查实际来源，避免原文或旧摘要掩盖问题。复杂方案没有胜过简单方案的预设义务。

需求方随后明确批准“完整原型优先”：M2 改为下述代表性完整过程与关键边界门禁；原150序列、统计质量与规模验证移至 M5，不再阻止 M3 原型接入。M0–M5、逐阶段检查与 push 顺序保持；旧失败、原评分阈值与未完成项保留，不把短案例成功冒充长期可靠性。核心行为契约不变。

### 遇到显著瓶颈时的第一性原理复审

需求方明确要求：后续遇到显著瓶颈、持续卡住或发现原有设计可能有问题时，像 M2 一样通过 GCP 调用 Gemini 4，作为独立评判与思考伙伴。此要求适用于后续各里程碑，不需要等到用户再次提醒。

1. 先重新陈述为什么要做、用户需要什么可观察结果，以及不可突破的约束；提供实际失败、成本和已有证据，区分事实与假设，不把当前实现方式预设为答案。
2. 必要时安排互补视角的 subagent，分别审视目标、设计和实现，再与 Gemini 4 讨论；已有结构、投入和测试数量都不构成保留设计的理由。
3. 若首轮质疑或分歧显著，先反思再继续讨论，双方始终从目标和基本约束出发。将分歧收敛为可被证伪的问题，用现有入口做最小实验，不以反复讨论或扩大验证设施替代整体可行性验证。
4. 记录关键异议、取舍与实测结果；模型共识不能代替验收证据。改变核心目标、行为契约或阶段门槛仍按第7节与需求方对齐，继续推进不依赖该决定的工作。实际模型不可用时如实记录，不冒充已完成独立复审。

## 2. 成功的定义

| 能力 | 可观察的结果 |
|---|---|
| 跨时间找回 | 低频、相隔多月的相关来源进入上下文；不只命中最近摘要 |
| 自适应组织 | 一段话可关联多个主题；主题与关系从数据产生，可拆分、合并和重新解释 |
| 指代处理 | 代词、昵称、别名、缩写、口误和描述可对应候选对象；证据不足时保留未知 |
| 多步推理 | 结论引用可核查前提，说明缺口与反证；没有材料时允许不能确定 |
| 持续修正 | 纠正影响正确范围；旧任务、缓存、原文检索与摘要不能绕过已知失效状态 |
| 有用地使用 | 与当前话题相关，区分用户表述、证据与推测；不产生额外通知 |
| 可运行 | 跨身体补齐、重启恢复、降级、自动部署、备份恢复可通过本机验收 |

不能把节点数量、关系数量、模型自评、一次演示成功或一组假模型测试作为整体成功证明。

## 3. 架构与当前代码边界

目标链路：各身体保存消息 → 现有认证网状层复制 → 记忆主机持久登记任务 → 增量理解 / 修正 / 研究 → 持久认识与可重建索引 → 当前话题的记忆材料 → 主模型回应。

| 位置 | 已核对的现状 | 本计划的改动方向 |
|---|---|---|
| `runtime/src/store.ts` | `addMessage` 本机写入与 `applyRemote` 远端应用是不同路径 | 两条路径统一纳入增量登记；启动补扫封闭崩溃窗口 |
| `runtime/src/mesh/replica.ts` | 实时复制、连接补齐、`replica.applied` 事件 | 复用来源认证与复制；事件只加快处理，持久状态才决定是否漏做 |
| `runtime/src/mind/brain.ts` | `learnTurn` 为有界内存 Promise 队列，满时跳过 | 加入可恢复的持久任务，避免与旧学习器重复拥有同一写入职责 |
| `runtime/src/mind/context.ts` | 逐请求选择记忆并按候选模型窗口准备 | 加入带版本、新鲜程度、来源和未知项的记忆材料，超时降级 |
| `runtime/src/memory/structured.ts` | 长期结构化认识以私有灵魂 Markdown 为权威，SQLite 为来源 / 派生状态 | 保持可迁移的权威记录；明确新认识的格式、读写门禁与发布协议 |
| `engine/` | 不依赖 runtime，承载纯策略和执行端口 | 通用规则可进入 engine；数据库、网状层、进程与供应商实现留宿主 |
| `cli/` 与平台适配器 | 已有安装、守护、健康检查及回滚流程 | 在职责边界内自动管理新服务；不能要求使用者手动启动 Python 或数据库 |

`docs/DISTRIBUTED.md` 保留早期设计与历史现状；涉及当前消息复制、字段与入口时，以实际源码和最新全局文档为准。本计划不将其早期“只有 Git 共享”描述作为现状。

原始对话仍属于既有 SQLite 来源体系；需要持久承诺保留的认识属于私有灵魂记录；图、向量、查询缓存是派生视图。具体跨 SQLite / 文件的发布、恢复、版本协议须在 M1 冻结并测试，不能依赖跨系统原子事务的假设。若改变灵魂规范，必须同步升版及相关实现、兼容与测试。M0 不修改规范或现有格式。M1 实现的[发布与恢复协议](ADAPTIVE_MEMORY_STORAGE.md)使用既有私有 Markdown 目录，未改变灵魂规范；测试与未完成边界逐批记录。

备份必须区分原始对话、长期认识、运行任务和可重建索引。只有灵魂 Git 无法保证完整对话重建；只有原文加新模型重跑，也无法保证恢复原有推断和人工纠正。

## 4. 实施顺序与门禁

| 阶段 | 交付范围 | 必需验收与进入下一阶段的条件 |
|---|---|---|
| M0 目标与契约 | 本计划、行为契约、逐步案例、指标、决策与验证记录；全局 / 模块文档入口 | 文档链接、编号、案例覆盖、源码依据、计划与现状区分、Git 范围检查通过；本地提交并 push 成功 |

## 6. 时间、性能与评测组织

- 前台只做有界读取，普通记忆读取初始目标为新增耗时 P95 ≤ 300 毫秒，500 毫秒读取截止后降级；统计包含网状层请求和服务查询，不能只计数据库执行时间。
- 正常负载下普通增量首轮处理初始目标为 P95 ≤ 60 秒；深度研究不计入这个指标，必须单独报告排队与运行时间。先短暂合并输入，再按最大等待时间调度，不无限等待“空闲”。
- 以上为待测目标，不是现有性能声明。M1 先以可控假模型测链路；M4 必须以真实模型测整体。若目标无法达到，记录原因并对齐修改，不静默放宽。
- 三组对照：当前 Quetzal；原文＋全文 / 向量检索；新记忆系统。使用相同主回答模型、输入顺序和查询检查点；分别报告后台预计算和线上调用成本，不能隐藏更高投入。
- 工程不变量要求确定性测试全部通过。语义阈值、样本量和重复次数在打开留出集前登记；失败结果必须保留。本 GOAL 使用自动化与代理评审并标明证据边界；真人帮助程度在完成后另行统计，不作为当前门槛。

## 7. 核心设计问题的对齐规则

这些情况必须先提出具体问题、影响与选项，暂停依赖该决定的实现，继续不受影响的工作：

1. 必须改变“长期认识随灵魂迁移”的权威存储原则，或无法保留来源与纠正历史。
2. 为满足组件接口必须不可逆合并实体、丢弃未决指代、把推测自动升为事实。
3. 必须改变跨 agent 隔离、现有来源权限或模型侧不能自行确认个人事实的门禁。
4. 需要向公共服务发送私人记忆正文，或把固定中心扩展为自动迁移 / 多中心写入。
5. 无法满足前台响应目标，必须让普通对话等待完整学习 / 深度研究。
6. 需要用户在正常使用中操作源码、数据库或服务进程。
7. 用户要求彻底删除历史，涉及 Git 历史、备份与离线副本；不得把“停止引用”冒充物理删除。
8. 核心语义质量达不到预登记门槛，或新系统相对基线没有可证实收益。

当前已确认的设计决策足以继续实施。具体主机操作系统、模型连接和本机测试环境属于实施配置，按实际可用环境检查；缺少访问时如实记录并处理；缺少真人反馈不阻塞本 GOAL，也不虚构已获真人认可。
